### 11-07（P0）前 3 关有趣：教学闭环 ✅ 已完成

**目标**：三关连续可玩；第 2 关的"停靠"、第 3 关的"借停"都能被玩家自己发现。

**产出**

- `levels.js` 写入第 1–3 关（数据见 GDD §6）。
- 教学文案常驻底部；卡住时给二次提示：**15 秒无操作**或**连续 3 步没有任何消除**触发（每关一次）。
- 步数上限、撤销（退还步数）、重开、失败后续玩、胜负判定、三星结算、进度/最好成绩存档。
- 玩法弹窗（首次进入，`?` 可重看）；静音开关；五类音效。

**与计划的偏差（有意）**

- 步数用 `2 / 6` 数字而不是点阵：50 关阶段上限会到 12，点阵在手机上过密。
- 二次提示从 5 秒改为 15 秒/3 步：5 秒对第一次读规则的人太急，容易像"游戏在催"。
- **前 3 关按试玩反馈重排**：原第 1、2 关通关思路相同，合并为一关；原第 3 关前移；新第 3 关用"借它停车"把核心抉择摆到玩家面前。

**验收**

- [x] 从第 1 关开始，通关自动进下一关；第 3 关通关出现结算。
- [x] 撤销能回到上一步并退还 1 步；重开重置步数。
- [x] 步数归零出现"步数用完了"，可撤销/重开，不卡死。
- [ ] **自己不看提示，3 分钟内通关第 3 关**（需要真人试玩，11-14 记录）。

**关卡数据（机器验证）**

| 关 | par / 上限 | 首步数 / 最优首步 | 关键点 | 走错关键步 |
|---|---:|---|---|---|
| 1 碰一下（原 1+2 合并） | 2 / 6 | 10 / 2（两个方向消 B） | 拖拽 + 同色消除 + 异色挡路；挡路者本身是一对 | 先拖 A → 3 步（2 星） |
| 2 停在墙边（原第 3 关） | 3 / 5 | 7 / **1**（`R5C4` 向上） | 墙把 A 停在 `R4C4`，正好与另一块对齐 | 4 步（2 星，不卡死） |
| 3 借它停车（新） | 3 / 6 | 12 / **1**（`R1C2` 向下） | 挡路者也是刹车；先消 B 会失去停靠点 | 4 步（2 星，不卡死） |

> 三关的所有可达局面都做过穷举：**没有任何"还有步数但无路可走"的死局**（deadEnds = 0）。第 2、3 关的关键步只影响星级，不影响能否通关。

**风险**：如果第 3 关自己都要试 3 次以上，说明教学文案或落点提示不到位——先改提示，不改关卡。

## 2. 关卡入库标准（Gate）

一关只有**全部**满足以下条件，才允许进入 `levels.json`：

| # | 检查 | 阈值 | 适用 |
|---:|---|---|---|
| 1 | 可解 | A\* 找到解 | 全部 |
| 2 | par ≤ 上限 | `limit >= par` | 全部 |
| 3 | 上限不冗余 | `limit - par` 在阶段区间内 | 全部 |
| 4 | 目标色合法 | 存在且数量为偶数 | 清色关 |
| 5 | 规模 | 方块 ≤ 12，颜色 ≤ 5 | 全部 |
| 6 | 反无脑 | 贪心失败 | #3 起 |
| 7 | 反乱滑 | 乱滑@par = 0% | #6 起 |
| 8 | 反边境高速路 | 中腹停靠 ≥ 1 | #9 起（清色关可放宽到"最佳解含 1 次非消除铺垫"） |
| 9 | 去重 | 盘面哈希不重复 | 全部 |
| 10 | 人工可复现 | 按 `sol` 在游戏内走一遍 | 抽查 10 关 |

> 第 6、7、8 条是这份研究最重要的产出：它们把"这关好不好"从主观判断变成了可执行的门槛。

## 3. 校验流程

### 3.1 命令

```bash
# 1. 全量校验（会回写 par，失败则非 0 退出）
node tools/verify.mjs

# 2. 单关调试（打印棋盘、par、解法、贪心、乱滑）
node tools/verify.mjs --id 3 --verbose

# 3. 生成候选
node tools/gen.mjs --stage 4 --count 40 --out research/candidates.json

# 4. 复跑研究数据（可选）
node research/experiments.mjs
node research/density.mjs
```

### 3.2 期望输出

```
levels=50 failed=0
  worst-slack: #44 (par 7 / limit 8)
  greedy-fail: 47/50
  rand@par>0: #1(6%) #2(9%) #3(1%)   ← 仅教学关允许
  max-expanded: #50 (39256)
```

### 3.3 失败处理

| 报错 | 处理 |
|---|---|
| `UNSOLVED #id` | 丢弃该关，重新生成；不要手改步数上限来"救" |
| `par > limit` | 提高上限或换盘面；连续 3 关出现说明生成参数太激进 |
| `odd target color` | 目标色改为偶数块，或换目标色 |
| `rand@par > 0`（#6 起） | 关卡太松：减少步数上限或加内墙 |
| `no mid-stop`（#9 起） | 加 1 面墙打断边境线，或换盘面 |
| `duplicate board` | 换盘面 |

### 3.4 回归纪律

- **每次改关卡数据，必须跑全量 verify**，不允许只测改的那一关。
- `par` 只由脚本写，人不手填。
- 提交前把 `levels_report.json` 一起提交，作为可复算的证据。

## 4. 试玩记录模板

**基本信息**：日期 / 设备 / 是否玩过同类游戏 / 是否玩过本作

| 关卡 | 用时 | 失败/重开次数 | 用撤销 | 用提示 | 卡在哪一步 | 原话（最重要） | 情绪 1–5 |
|---:|---:|---:|---|---|---|---|---:|
| 1 | | | | | | | |
| 2 | | | | | | | |
| 3 | | | | | | | |
| 6 | | | | | | | |
| 10 | | | | | | | |
| 20 | | | | | | | |

**必问的 4 个问题**

1. "刚才第 3 关，你为什么先把最下面那块往上拖？"（验证"墙是刹车"是否被理解）
2. "如果只能用一个词形容这个游戏，你会说什么？"
3. "哪一关让你想再来一次？哪一关让你想关掉？"
4. "你觉得'消掉一对'是好事还是坏事？为什么？"（验证微创新是否被感知）

**判定**

- 问题 1 答不出 → 教学失败，改文案/加落点提示。
- 问题 4 答"当然是好事" → 微创新没被感知，需要在第 3 阶段前加一关"消错了反而堵死"的反例。
- 第 10 关前出现"想关掉" → 曲线太陡，把 S2 的 par 带整体降 1。
