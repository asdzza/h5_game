**与 GDD 的一处订正**

- [x] 6 步内可达 90386 个局面，死局 0。

**生成器用法**

```bash
npm run gen -- --template two-shafts --blocks A2B2C2 --goal clear --par 6 --limit 10 --tries 400
```

- `--blocks`：颜色 + 数量，如 `A2B2C2`（颜色 A–E，大小写不敏感）。
- `--goal`：`clear` 或某个颜色（如 `A`）；清色目标必须≥2 且成对。
- `--par` / `--limit`：目标 par 与步数上限（`limit` 默认 `par+3`）。
- `--tries` / `--seed`：随机盘面数与种子，固定种子可复算。
- `--top` / `--path` / `--json`：输出几个候选、给前几个打印最优路径、末尾输出 JSON。
- `--no-open-pop`：去掉开局就有现成一对的盘面。
- `--all-recoverable`：只留"任何首步之后都还能在上限内通关"的盘面。
- `--dead`：对最终候选扫死局（较慢，节点上限可用 `GEN_DEAD_NODES` 调）。

**验收**

- [x] `node tools/verify.mjs` 能跑完当前 8 关，输出 `levels=8 failed=0`。
- [x] 故意改坏一关（把第 6 关最后一块 C 改成空）→ 输出 `# 6 FAIL ... 清场模式方块数 5 是奇数` / `声明的 par=6 步内无解`，退出码 1，并指出关卡号。

## 3. 校验流程

### 3.1 命令

```bash
# 1. 全量校验（会回写 par，失败则非 0 退出）
node tools/verify.mjs

# 2. 单关调试（打印棋盘、par、解法、贪心、乱滑）
node tools/verify.mjs --id 3 --verbose

# 3. 生成候选
node tools/gen.mjs --stage 4 --count 40 --out research/candidates.json

# 4. 复跑研究数据（可选）
node research/experiments.mjs
node research/density.mjs
```

### 3.2 期望输出

```
levels=50 failed=0
  worst-slack: #44 (par 7 / limit 8)
  greedy-fail: 47/50
  rand@par>0: #1(6%) #2(9%) #3(1%)   ← 仅教学关允许
  max-expanded: #50 (39256)
```

### 3.3 失败处理

| 报错 | 处理 |
|---|---|
| `UNSOLVED #id` | 丢弃该关，重新生成；不要手改步数上限来"救" |
| `par > limit` | 提高上限或换盘面；连续 3 关出现说明生成参数太激进 |
| `odd target color` | 目标色改为偶数块，或换目标色 |
| `rand@par > 0`（#6 起） | 关卡太松：减少步数上限或加内墙 |
| `no mid-stop`（#9 起） | 加 1 面墙打断边境线，或换盘面 |
| `duplicate board` | 换盘面 |

### 3.4 回归纪律

- **每次改关卡数据，必须跑全量 verify**，不允许只测改的那一关。
- `par` 只由脚本写，人不手填。
- 提交前把 `levels_report.json` 一起提交，作为可复算的证据。

| 保留 | 砍掉 |
|---|---|
| 规则内核 + 拖拽 | 粒子、震屏 |
| 前 12 关（含第 3–12 关教学） | 音效 |
| 20 关（S1+S2 精选） | 关卡选择页（改为线性"下一关"） |
| 步数 + 撤销 + 重开 | 提示、阶段完成页 |
| 单页部署 + README | 存档（每次从头开始也能玩） |

**底线**：**宁可 20 关全绿，不要 50 关里有 5 关过不去。** 评委会原谅关卡少，不会原谅卡死。

## 7. 每日收尾（30 秒）

每天结束前做三件事，防止第二天从零开始：

1. `git commit`（或复制一份带日期的压缩包）。
2. 在 `docs/开发日志.md` 写 3 行：今天做完什么、卡在哪、明天第一件事。
3. 跑一次 `node tools/verify.mjs`，确认没有回归。
