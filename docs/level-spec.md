# 关卡数据规范（`src/levels.js`）

> 新增 / 修改关卡时先读这一页。规则语义见 `docs/rules.md`。
> 所有关卡数据都是纯数据，不允许在 `levels.js` 里写运行时逻辑。

## 1. 对象结构

```js
{
  id: 45,                     // 1..50，唯一，选关页与存档都依赖它
  stage: 5,                   // 1..5，决定选关页分组
  name: '两段路',             // 短名，6 字以内优先
  goal: 'clear',              // 'clear' | 'color'
  targetColor: 1,             // goal === 'color' 时必填，1..5（红蓝绿黄紫）
  limit: 12,                  // 步数上限，必须 >= par + 1
  par: 9,                     // 求解器最少步数
  challenge: true,            // 可选：选关页 / HUD 的 ⚑ 标识
  caution: '这关难在…',       // 可选：挑战关进关时先播 6.5 秒
  teach: '本关规则的一句话',  // 进关常驻提示
  nudge: '一条可行路线…',      // 分层提示第 2 层用，禁止写「唯一解」
  rows: [                     // 7 列字符串数组，高度不限
    '#######',
    '#..BDD#',
  ],
}
```

字段约定：

- `teach` 只讲本关可观察的规则，不写坐标、不写解法。
- `nudge` 是「一条可行路线」，不是「唯一最优解」；多解是设计目标。
- `challenge` 只做预期管理，不扣星、不影响解锁。
- 调 `limit` 时必须同步复查星级线（`starsFor`）与失败页预算。

## 2. 字符表

| 字符 | 含义 | 说明 |
|---|---|---|
| `#` | 墙 | 阻挡所有颜色 |
| `.` | 空位 | 可通行 |
| `A`–`E` | 普通方块 | 红 / 蓝 / 绿 / 黄 / 紫 |
| `a`–`e` | 锚块 | 拖不动；同色撞上一起消失 |
| `f`–`j` | 泊位 | 对应 A–E；同色停入一次永久打勾 |
| `1`–`5` | 最后一对 | 对应 A–E，并把该色设为 `lastColor` |

一行里可以同时出现普通块、锚块、泊位和数字标记；同一颜色允许部分用字母、
部分用数字（数字只负责打标记，不改变颜色）。

## 3. 完整示例

`#45 两段路`（首个泊位关，par 9 / limit 12）：

```js
{
  id: 45,
  stage: 5,
  name: '两段路',
  goal: 'clear',
  limit: 12,
  par: 9,
  teach: '棋盘被分成上下两段：紫色有一格泊位（盘面中间的紫色虚线格），紫块要停进去一次才算完成；同一面墙只够一块用，谁先占用，另一段就少一个停靠点。',
  nudge: '先把第2行第5列的黄块向右推……',
  rows: [
    '#######',
    '#..BDD#',
    '#E##E.#',
    '#EE.jC#',
    '#.C##.#',
    '#AA..B#',
    '#######',
  ],
}
```

`j` 是第 5 色（紫）的泊位。

## 4. 新增关卡的固定流程

1. 用生成器 / 搜索脚本产出候选盘面，先写进 `research/`，不要直接改游戏。
2. 用 A\* 求 `par`，并检查：
   - 每个首步都能在 `limit` 内通关；
   - 保持 `par` 的首步数量符合该章目标（通常 2–8 个）；
   - 非目标色 / 整组墙拿掉后 `par` 有变化（承重）。
3. 确认没有「贪心能过 / 随机乱滑能过」的假难度。
4. 写入 `src/levels.js`，同时把一条最优路线写进 `src/solutions.js`
   （长度必须等于 `par`）。
5. 跑：

```bash
node tools/verify.mjs     # 期望 levels=50 failed=0
npm test                  # 全量规则回归（约 290 秒）
```

## 5. 常见坑

- `limit` 小于 `par + 1`：`verify` 直接失败，且玩家没有容错。
- `goal: 'color'` 忘记 `targetColor`：目标判定会拿 `undefined` 去比。
- 数字标记只标了颜色的一部分：`lastColor` 仍然生效，但视觉上容易让玩家误判；
  要么全标，要么不标。
- 泊位放在锚块 / 墙上：`parse` 不报错，但永远停不进去，容易做出无解关。
- 只改 `par` 不改 `solutions.js`：回放长度校验会失败。
- 只改 `limit` 不改 README / 迭代文档：提交材料与游戏内数据不一致。

## 6. 调试入口

本地 / `127.0.0.1` / `file://` 下会暴露 `window.__zgz`：

```js
__zgz.selectLevel(44);   // 走完整选关流程（含新规则卡）
__zgz.loadLevel(44);     // 只装载关卡，不弹规则卡
__zgz.state;             // 当前盘面
__zgz.history;           // 每一步前的快照
__zgz.moves;             // 已用步数
```

生产环境（GitHub Pages）不暴露该对象。
