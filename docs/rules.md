# 《撞个正着》规则与验收口径

> 面向后续开发 / AI 协作的规则单页。关卡数据格式见 `docs/level-spec.md`，
> 本轮改动见 `docs/changelog.md`。代码实现以 `src/game.js` 为准。

## 1. 一句话玩法

拖一个方块，它会沿方向一直滑；撞上同色方块，两块一起消失。
消除只移除、不新增，所以每消一对也等于拆掉两块「刹车」。

## 2. 一次操作如何结算

按以下顺序判定（实现见 `traceMove` / `moveFrom`）：

1. 锚块（钉子）不能被拖动；拖它只给「被钉死」反馈，不消耗步数。
2. 沿方向逐格前进，直到发生下面任一情况：
   - 撞墙 / 边界：停在最后一个空格；若一步都没动，这一手非法。
   - 撞异色块：停在它旁边，不推动。
   - 撞同色块：两块一起消失。
3. 与「最后一对」冲突时，这一手非法，不消耗步数（见 §4.3）。
4. 合法移动会消耗 1 步；步数用满且未达成目标即失败。

## 3. 盘面符号

| 字符 | 含义 |
|---|---|
| `#` | 墙 |
| `.` | 空位 |
| `A`–`E` | 红 / 蓝 / 绿 / 黄 / 紫方块 |
| `a`–`e` | 同色锚块（钉子），拖不动，同色撞上一起消失 |
| `f`–`j` | A–E 颜色的泊位（空位，彩色虚线格） |
| `1`–`5` | A–E 颜色，并把这色标成「最后一对」 |

盘面固定 7 列；每关的 `rows` 长度可以不同，但同一关必须等宽。

## 4. 三种「停法」

### 4.1 锚块（钉子）

- 不能被拖动，异色照常被它挡住。
- 只有同色块撞上去，锚块才连同两块一起消失。
- 锚块被撞掉后，该格恢复为空位。

### 4.2 泊位

- 彩色虚线格，对应颜色停进去一次即打勾。
- 打勾是永久的：方块之后离开，勾不会掉。
- 通关要求「目标达成 + 所有泊位都打勾」。
- 泊位在 `parse` 时写入 `berths`，完成状态是 `filled` 位掩码。

### 4.3 最后一对

- 带方格旗的颜色必须留到整盘最后。
- 该色还有 4 块时可以先消一对；只剩 2 块且场上还有别的颜色时，这一撞非法。
- 被挡住时给「这是最后一对」提示，不消耗步数。

## 5. 目标类型

| `goal` | 通关条件 |
|---|---|
| `clear` | 清空全场，且所有泊位已停 |
| `color` | 指定 `targetColor` 全部消失，且所有泊位已停 |

目标色关卡里，其他颜色消掉不会推进目标；游戏会明确提示「不算目标」。

## 6. 步数、星级、失败与回退

- `par`：求解器算出的最少步数；`limit`：本关步数上限，必须满足 `limit >= par + 1`。
- 星级：`3★ = par`；`2★ = par + max(1, round((limit - par) / 2))`；其余 `1★`。
- 提示扣星只在本次尝试内有效；重开 / 再玩一次 / 从选关页重进即清零。
- 失败页先显示诊断：还差几对、还差几个泊位；随后后台 Worker 从历史快照里
  找「最后还能赢的一步」。
- 「回到第 N 步（还有救）」直接恢复到该快照，比连点撤销便宜；找不到时退化为
  「撤销一步 / 重开本关」。

## 7. 关卡验收

`node tools/verify.mjs` 必须输出 `levels=50 failed=0`。核心门槛：

- 每关可解，且预置解法长度等于 `par`。
- `limit - par >= 1`。
- 首步在 `limit` 内全部可通关；保持 `par` 的首步数量符合该关设计。
- 墙 / 非目标色必须「承重」：拆掉整组后 `par` 应有变化（例外需在关卡注释说明）。
- 死局判定与 `research/engine.mjs` 对拍一致。

完整规则回归跑 `npm test`（约 290 秒），结构体检跑 `npm run verify`。

## 8. 体验约束（本轮新增）

- 默认 50 关全部可选；`?locked=1` 才逐关解锁。评委可以跳关看后期设计。
- 新机制第一次出现时用规则卡讲一次，帮助页的后期规则默认折叠。
- 鼠标悬停可拖方块显示 `grab` + 描边；钉子显示 `not-allowed`。
- HUD 常驻「还差 N 对」「泊位 x/y」；剩余 1–2 步时提示优先显示步数。
