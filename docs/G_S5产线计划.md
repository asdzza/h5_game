# S5（41–50）精算段产线计划

> 目标：在 S4「先解哪一对」之上，把容错收紧到 `limit = par + 1` 或 `par + 2`，让玩家为每一步精打细算。
> 这一段不再靠加颜色、加墙、扩大棋盘制造难度；主杠杆只有两个：**顺序耦合**与**容错收紧**。

---

## 1. 规格

- 关卡：41–50，共 10 关。
- 规模：统一 12 块 / 4–5 色 / 3–5 格内墙，棋盘保持 7×7。
- par：7–10；上限：只比 par 多 1–2 步。
- 目标：7 关清场；#43 / #44 / #48 保留清色，避免目标切换断档。
- 难度口径：`难度 ≈ 决策数 × 诱惑强度 × 走错代价`；S5 把第三项从「多花 2 步」压到「几乎直接超上限」。
- 实际取舍：`par+1` 与「所有首步都能在上限内通关」几乎不可兼得，最终 **8 关用 par+2，仅 #43 / #48 用 par+1**（严格通过 A–J 全部门槛）。

## 3. 验收门槛

| 代号 | 门槛 | 检查方式 |
|---|---|---|
| A | par 命中，`limit - par` 为 1 或 2 | `s4_check --par/--limit` |
| B | 所有首步都能在上限内通关，死局 0 | `verify --dead --first` |
| C | 保持 par 的首步 2–8 个；至少一个首步被惩罚 | `s4_check` |
| D | 整组墙拆掉后 par 必降；最优路径至少一次墙停 | `s4_check` |
| E1 | 清场关：每种颜色整色拿掉后 par 必降；至少两种降 ≥2 步 | `s4_check` |
| E2 | 清色关：每种非目标色整色拿掉后 par 必变；目标色块数为偶数 | `s4_check` |
| F | 顺序压力 ≥1：最优路径上至少一处「≥2 个可消对，且至少一个错选被惩罚」 | `s4_check` |
| G | 可读性：10–12 块、4–5 色、3–5 格内墙 | 人工 + 脚本 |
| H | 不允许唯一首步；保持 par 的首步至少 2 个 | `s4_check` |
| I | 上限收紧：`limit ∈ {par+1, par+2}`，至少 2 关为 `par+1` | `s5_batchcheck` |
| J | 盘面不与 1–40 关重复 | 哈希去重 |

> 实际结果：仅 #43、#48 为 `par+1`，其余 8 关均为 `par+2`；保持 par 的首步 8/6/4/7/8/8/5/4/7/5 个，全部在 C 的 2–8 区间内。

## 4. 工具

- `research/s4_core.mjs`：分析内核，S5 直接复用 `analyze()` / `gateChecks()`。
- `research/s4_check.mjs`：单盘终检；S5 盘面仍为 7×7，可直接用。
- `research/s5_hunt.mjs`：变异搜索器（低内存模式）。A* 预筛 cap 6 万、完整分析 cap 20 万；任一子解撞上限就丢弃；每找到一个候选立即写盘，适合长时间后台跑。
- `research/s5_batchcheck.mjs`：41–50 批量终检，额外检查 `limit - par`、块/色/墙规模。
- `research/s5_insert.mjs`：从 `research/s5_found/*.json` 复验 10 个初选盘面，通过后 `--write` 追加到 `src/levels.js`。
- `tools/test_rules.mjs`：§4.23 对 41–50 做通用断言（par / 首步 / 整色载荷 / 墙载荷 / 规模 / 容错）。

### 搜索与入库示例

```bash
# 低内存搜索：12 块 / 5 色 / 3–5 墙 / 清场
node research/s5_hunt.mjs --tag l41c --base 34,37,39,40 --goal clear --par 9 --limit 11 --blocks 10-12 --walls 3-5 --colors 5 --tries 400 --seed 4103 --top 3 --mutations 1

# 清红关：par 8 / 上限 9（容错只多 1）
node research/s5_hunt.mjs --tag l43 --base 38 --goal color --target 1 --par 8 --limit 9 --blocks 10-12 --walls 3-5 --colors 4-5 --tries 300 --seed 4301 --top 3

# 只复验初选盘面（不写库）
node research/s5_insert.mjs
# 复验通过后写入 src/levels.js
node research/s5_insert.mjs --write

# 批量终检
node research/s5_batchcheck.mjs --from 41 --to 50
```

## 6. 风险与回退

1. **`par+1` 搜索通过率低**：实际搜索中「所有首步都能在上限内通关」与 `par+1` 几乎不可兼得，最终只保留 #43 / #48 两关 `par+1`，其余放宽到 `par+2`；不降低首步可恢复门槛。
2. **五色读图**：S5 以 5 色为主，但控制在 12 块；#43 / #44 / #48 只保留 4 色，避免清色关同时读五种颜色。
3. **A\* 内存**：早期 10 并行搜索曾占 7–8 GB。现固定 2–3 并行、cap 6 万/20 万、子解撞上限即丢弃；单个进程约 0.6–1 GB。
4. **回退**：任何一关未过 A–J，先用同 tag 的其他候选替换；仍不行再换种子重搜。绝不把未验证盘面上线。
