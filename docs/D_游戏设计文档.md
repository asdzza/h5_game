# D. 游戏设计文档（GDD）

**《撞个正着》**
一句话：**拖一个方块，它会一直滑到底；撞上同色方块，两块一起消失。**

| 项 | 内容 |
|---|---|
| 类型 | 2D 滑块解谜 / 休闲 |
| 平台 | 移动端 H5（竖屏优先），桌面浏览器可玩 |
| 单局时长 | 20–90 秒 |
| 关卡数 | 50（5 阶段：8 / 10 / 12 / 10 / 10，含 3 关教学） |
| 操作 | 单指拖拽（唯一操作） |
| 目标用户 | 等车、排队时想"动一下脑子"的轻度玩家 |
| 商业化 | 无。比赛作品，不做内购/广告 |
| 技术 | 原生 ES Module + Canvas 2D + WebAudio，无框架、无构建 |

> **证据说明**：本文件中所有 par、上限、方块数、贪心失败、乱滑通关率均来自 `research/` 的模拟器与求解器（可复跑）；所有"玩家会觉得 / 会记住 / 会想再来一关"都是**策划预测**，尚未经过真人试玩，需按 `docs/E` 的 11-14 试玩验证。

---

## 1. 设计目标与非目标

### 目标

1. **3 秒看懂，30 秒上手**：第 1 关不需要任何文字也能玩。
2. **每关只问一个问题**："这一对，现在消还是等会儿消？"
3. **失败不挫败**：没有时间压力，步数用完可以无限撤销。
4. **50 关不靠堆规模**：难度来自目标切换、几何、步数收紧，不来自"更大的盘 + 更多的块"。

### 非目标

- 不做剧情、角色、养成、联机、排行榜。
- 不做连锁、重力、道具、多指操作。
- 不追求美术精度：方块 + 圆角 + 颜色 + 一个符号，够了。
- 不做关卡编辑器（内部用 JSON + 脚本，不面向玩家）。

## 2. 核心规则（唯一权威版本）

### 2.1 棋盘

- 矩形网格，外圈是边界，内部可放**墙**（`#`）、**空位**（`.`）、**方块**（5 种颜色 A–E）。
- 每格至多一个方块。

### 2.2 一次操作

玩家按住一个方块，向上下左右任一方向拖动，松手后：

1. 方块沿该方向**逐格滑动**。
2. 下一格是**墙或边界** → 停在最后一个空格。
3. 下一格是**异色方块** → 停在它旁边，**不推动它**。
4. 下一格是**同色方块** → 移动块与目标块**同时消失**；移动块不占目标格。
5. 若移动 0 格且没有消除 → **无效操作，不扣步数**（松手回弹）。

### 2.3 目标与步数

- **清场关**：清空全部方块。
- **清色关**：只清除指定颜色；其他颜色可以留，也可以消（但消一对要花一步，还可能少一块可借的"刹车"）。
- 每关有步数上限。**用完且未达成目标 = 失败瞬间**（可撤销，见 §6）。
- 一次操作**最多消一对**。无连锁、无重力、无补位。

### 2.4 术语（内部统一叫法）

| 术语 | 含义 |
|---|---|
| **滑** | 移动但没消除 |
| **撞 / 消** | 与同色方块对撞并双双消失 |
| **停靠** | 方块停在非边界位置（通常是被墙或异色块挡住） |
| **中腹停靠** | 停在棋盘内部（非最外圈）——核心技巧的度量指标 |
| **借位** | 故意让某块停在某处，为下一步做铺垫 |
| **边境高速路** | 方块总能滑到边界、边界天然形成汇合线的结构性漏洞 |

## 3. 微创新：消除 = 拆墙

### 3.1 一句话

> 因为消除**只移除、不新增**，所以每消一对，等于**拆掉两堵墙**。核心抉择不是"消哪一对"，而是"**这一对现在消，还是留着当刹车**"。

### 3.2 为什么这条创新成立（不是包装）

| 证据 | 数据 |
|---|---|
| 最优解里"停在内部"的铺垫步普遍存在 | 13 个精选关卡中 **11 关**含至少 1 次铺垫步，其中 **10 关**含关键的中腹停靠 |
| 关键停靠步不可跳过 | 第 2 关禁掉 `R5C4↑` 后 par 从 3 → 4；7 个合法首步里只有 1 个保持 par。第 3 关同理：禁掉 `R1C2↓` 或先消 B，par 3 → 4 |
| "看到能消就消"不是正确策略 | 贪心策略在 **11/13 关**失败 |
| 乱走不能过关 | 第 6 关起，随机乱滑在 par 步内通关率 **0%** |

### 3.3 它改变了哪一种决策

| 普通消除游戏 | 《撞个正着》 |
|---|---|
| 消掉 = 得分 + 腾空间 | 消掉 = 得分，但**同时拆掉了两块可用的挡板** |
| 棋盘越空越好 | 棋盘**太空反而没地方停车** |
| 目标是"找能消的" | 目标是"**安排它们停在哪**" |

这就是全部创新。**不再加第二条。**

## 4. 反馈与奖励

### 4.1 一次操作的反馈时序（关键：让因果可见）

| 时间 | 表现 | 目的 |
|---:|---|---|
| 0 ms | 按住方块 → 放大 1.06、投影一层暗影 | 确认"抓住了" |
| 拖动 > 10 px | 判定主轴，出现**方向箭头** + **落点虚影** + 被撞目标描边 | 让玩家在松手前就知道结果 |
| 松手 | 输入锁定，开始滑动 | 防连点 |
| 每格 55 ms（总时长上限 260 ms） | 方块 easeOutQuad 滑行，带 0.9→1 的拖影 | 滑动有重量 |
| 撞墙/异色 | 停靠瞬间 60 ms 挤压（scaleX 1.12 / scaleY 0.9），回弹 | "刹住了"的手感 |
| 撞同色 | 40 ms 全屏顿帧 → 两块放大到 1.15 → 180 ms 缩到 0 + 6 个碎片粒子 | 消除的"砰" |
| 消除后 80 ms | 轻震 4 px / 手机 vibrate(15) | 触觉确认 |
| 结算前 200 ms | 剩余步数逐个跳动 | 给"省了几步"一个仪式 |

### 4.2 音效（WebAudio 合成，不加载素材）

| 事件 | 声音（首版实现） |
|---|---|
| 滑动 | 520 → 300 Hz 三角波，100 ms，低音量 |
| 撞墙 / 无效操作 | 170 → 110 Hz 方波，90 ms（"顶住了"） |
| 消除 | 620 Hz + 940 Hz 双音，130 ms（上行"叮"） |
| 通关 | C5-E5-G5-C6 琶音，每音 200 ms |
| 界面（关闭玩法卡 / 音效开关） | 740 Hz 正弦，50 ms |

> 静音开关常驻右上角（🔊/🔇），状态写入 localStorage；默认开声音。浏览器要求先有一次交互，第一次 pointerdown 时解锁 AudioContext。
> 首版不做"抓起"音：高频短音在连续拖动时容易变成噪音。

### 4.3 奖励结构

| 层级 | 奖励 | 规则 |
|---|---|---|
| 单关 | **1–3 星** | 3 星 = 步数 ≤ par；2 星 = 步数 ≤ par + 2；1 星 = 在步数上限内通关 |
| 单关 | "一次过"徽章 | 全程未使用撤销且 ≤ par + 1 |
| 阶段 | 阶段完成页 | 展示本阶段 10 关的星星总数 |
| 全局 | 50 关全三星 | 标题页显示"全清"标记（不做排行榜） |

**没有金币、没有体力、没有抽奖。** 奖励只做两件事：告诉玩家"你走得比最少步多几步"，以及"你可以再优化"。

### 4.4 失败反馈（不惩罚）

- 步数归零且未达成目标 → 棋盘上方浮出半透明条：**"步数用完了 · 差一点"**
- 两个按钮：**[撤销一步]**（退还 1 步）、**[重开]**
- 不做"失败音效"、不做红色闪烁、不扣星星（本来就没拿到）。
- 目标色没清完但还能动 → **不提前判负**，让玩家自己发现"已经没救了"。

## 5. 失败 / 重试 / 撤销

| 机制 | 规则 | 理由 |
|---|---|---|
| **撤销** | 无限次；回到上一步的棋盘 + 退还 1 步；反向动画 120 ms | 休闲玩家不该因为一次手滑重开 |
| **重开** | 任意时刻可用；无确认弹窗；重置步数与棋盘 | 确认框比误触更烦 |
| **失败** | 只有"步数耗尽"一种；无时间限制、无生命值 | 失败必须可归因于"我想错了"，不是"我手慢" |
| **提示** | 空闲 45 秒或连续 2 次重开后，提示按钮开始呼吸；点击高亮最优解的下一步（数据来自关卡 `sol`），**使用后本关最高 2 星** | 防卡死，同时保留三星的含金量 |
| **无效操作** | 0 位移且无消除 → 回弹，不扣步、不进撤销栈 | 避免"点一下也扣步"的隐形惩罚 |

**关于"撤销退还步数"的说明**：这看起来让步数上限失效，但实际不会——撤销只能退回**已经走过的**局面，玩家仍然必须自己想出正确顺序。步数上限约束的是"这一遍尝试的长度"，撤销约束的是"不许无限试错而不付时间成本"。对休闲玩家，时间成本已经足够。

## 6. 前 3 关完整设计

> 三关的目标不是"好玩"，是**在 3 分钟内把"拖—撞—挡—停—借"这条规则链走一遍**。11-07 按试玩反馈重排：原第 1、2 关合并（两关的通关思路相同），原第 3 关前移为第 2 关，新第 3 关把"借它停车"这个核心抉择摆到玩家面前。

### 6.1 第 1 关「碰一下」（原第 1、2 关合并）

```
      1 2 3 4 5
  1   A · B · A
  2   · · · · ·
  3   · · · · ·
  4   · · · · ·
  5   · · B · ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 6（par 2） |
| 方块 | 4（A×2，B×2） |
| 教学文案 | "拖动方块，它会滑到撞上东西为止。撞同色一起消失；异色会挡路，但它也有一对。" |
| 二次提示 | "先消掉中间挡路的 B：把它往下拖，A 的路就通了。要是 B 已经消了，直接让两个 A 对撞。" |

**通关步骤**

1. `R1C3` 的 B 向下 → 撞 `R5C3` 的 B → 双消
2. `R1C1` 的 A 向右 → 撞 `R1C5` 的 A → 双消

**设计意图**：把原第 1 关的"同色对撞"和原第 2 关的"异色挡路"压进同一关。玩家第一反应多半是拖 A；A 只滑到 `R1C2` 就被 B 挡住——这一下同时教了"滑到底"和"异色不会让路"。再把 B 消掉，A 的路就通了。少一关，但两个规则都在，而且第一次"被挡住"不扣命、不失败。

**失败点**：先拖 A 会被挡住，多花 1 步（3 步通关，2 星）；上限 6，不会失败。A 被挡住后也可以拖走再重试。

**验收标准**：不看文案的玩家能在 30 秒内通关；第一下拖 A 被挡住后，能在 1 次尝试内改拖 B；能说出"B 挡着，所以先消 B"。

### 6.2 第 2 关「停在墙边」（原第 3 关前移）

```
      1 2 3 4 5
  1   · · · · ·
  2   · · · · ·
  3   · · B ■ ·
  4   · · A · ·
  5   · · B A ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 5（par 3） |
| 方块 | 4（A×2，B×2） |
| 教学文案 | "墙也是刹车：方块会停在墙边，而「停下的位置」往往正是另一块需要的位置。" |
| 二次提示 | "别只想着滑到底：往上拖 A，墙会把它停在另一块 A 旁边。" |

**通关步骤**

1. `R5C4` 的 A 向上 → 被 `R3C4` 的墙挡住，停在 `R4C4`
2. `R4C3` 的 A 向右 → 撞 `R4C4` 的 A → 双消
3. `R3C3` 的 B 向下 → 撞 `R5C3` 的 B → 双消

**设计意图**：玩家直觉是"往上拖会滑到顶"，但墙让它停在 `R4C4`——正好贴在另一块 A 旁边。**"墙替你踩了刹车"** 这个结果完全符合规则，却是第一次遇到。

**数据支撑**：7 个合法首步里**只有 1 个**保持 par；禁掉它，par 从 3 → 4（仍在上限 5 内，不会卡死，但拿不到三星）。

**失败点**：先把 `R3C3` 的 B 往上挪开（`R3C3` 向上）会多花 1 步：A 仍能靠墙停车，但 B 要再滑一次才能消，4 步通关拿 2 星。**这是"可接受的失败"：不卡死，但玩家能感到"我好像绕远了"。**

**验收标准**：玩家在 30 秒内主动把 A 往上拖（而不是先动 B）；通关后能复述"墙把它挡住了，正好停在另一块旁边"。

### 6.3 第 3 关「借它停车」（新）

```
      1 2 3 4 5
  1   · A · · ·
  2   · · · ■ ·
  3   · · · A ·
  4   · B · B ·
  5   · · · · ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 6（par 3） |
| 方块 | 4（A×2，B×2） |
| 教学文案 | "有时候挡住去路的方块不是障碍，而是刹车——先别急着消掉它。" |
| 二次提示 | "把左上角的 A 往下拖，让它停在第三行；B 能接住它。要是 B 已经消了，先撤销。" |

**通关步骤**

1. `R1C2` 的 A 向下 → 被 `R4C2` 的 B 挡住，停在 `R3C2`（正好和 `R3C4` 的 A 同行）
2. `R3C2` 的 A 向右 → 撞 `R3C4` 的 A → 双消
3. `R4C2` 的 B 向右 → 撞 `R4C4` 的 B → 双消

**设计意图**：这是全篇最像"核心抉择"的一关。玩家刚在第 1 关学会"挡路者也是一对，先消它"，第 3 关却给出一个几乎一样的分组：A 被 B 挡着。但这次 B 不在 A 的去路上，而是在它下方——A 往下滑会停在 B 上面，正好和另一块 A 对齐。先消 B 会失去刹车，A 直接滑到底，虽然仍能通关，但要多花 1 步。**"借它停车"还是"把它消掉"，就是这款游戏的核心抉择。**

**数据支撑**：12 个合法首步，只有 1 个保持 par（`R1C2` 向下）；先消 B（`R4C2` 向右）后，最优变 4 步（2 星）；禁掉关键步同样 4 步。所有可达局面 **deadEnds = 0**；最坏局面仍能在 6 步内收尾（上限 6）。

**失败点**：先消 B 后 A 会滑到底，但 `R3C4` 的 A 可以往下走，两块 A 仍能在 4 步内相接；不卡死，只是少一颗星。

**验收标准**：玩家在 30 秒内先尝试拖 A（而不是先消 B）；通关后能说出"B 把它挡住了，正好停在另一块旁边"。

### 6.4 三关的实机参数（11-07 已实现）

| 项 | 第 1 关 | 第 2 关 | 第 3 关 |
|---|---|---|---|
| par / 上限 | 2 / 6 | 3 / 5 | 3 / 6 |
| 合法首步 | 10 | 7 | 12 |
| 保持最优的首步 | 2 | **1** | **1** |
| 走错关键步后的最优 | 3（2 星） | 4（2 星） | 4（2 星） |
| 可达死局（有步数但无路） | 0 | 0 | 0 |

- 失败只在"步数用尽且未清空"时触发；弹窗提供「撤销一步」（退还 1 步）与「重开本关」，不会出现只能看广告/退出重来的死路。
- 三星门槛：≤ par；两星 ≤ par+2；其余一星。第 1 关先拖 A 的 3 步仍是 2 星；第 2、3 关的 4 步诱惑解也是 2 星。第 3 关只有连续绕远到 6 步才会 1 星。
- 卡住提示：15 秒无操作，或连续 3 步没有消除，底部换一句更具体的提示（每关只出现一次），不直接给完整解法。
- 撤销是无限的，但只回退到"已经走过的局面"；步数上限约束的是这一遍尝试的长度。

> 实测补充：第 2 关的 4 步替代解（先 `R3C3` 向上，再 `R5C4` 向上，`R4C3` 向右消 A，`R1C3` 向下消 B）能通关且拿 2 星。它证明"没发现墙的用法"不会卡死，只会少一颗星。第 3 关先消 B 的 4 步解同理。

## 7. 50 关难度曲线

### 7.1 五个阶段

| 阶段 | 关卡 | 主题 | 目的 | 块/色 | 墙 | par 带 | 上限 |
|---|---|---|---|---|---|---:|---|
| **S1 教学** | 1–8 | 学会看 | 拖、撞、挡、停、借、顺序 | 4–6 / 2–3 | 0–2 | 2–6 | par+4 → +3 |
| **S2 几何** | 9–18 | 学会绕 | 缺口、凹形、窄道打断"边境高速路" | 6–8 / 3–4 | 2–3 | 5–9 | par+3 |
| **S3 目标** | 19–30 | 学会取舍 | 从"清完"变成"只清目标色" | 8–10 / 3–4 | 2–3 | 3–7 | par+3 → +2 |
| **S4 耦合** | 31–40 | 学会排序 | 4–5 色互相挡路，先解哪一对 | 10–12 / 4–5 | 3–4 | 7–10 | par+2 |
| **S5 精算** | 41–50 | 学会省 | 上限只比 par 多 1–2 步 | 10–12 / 5 | 3–5 | 7–10 | par+2 → +1 |

### 7.3 曲线的三条硬约束

1. **par 涨幅逐段收窄**：S1 2→6，S2 5→9，S3 3→7（目标变了，par 回落是故意的），S4 7→10，S5 7→10。**不允许单调上升**——S3 开头的"回落"是给玩家一次"我很行"的呼吸。
2. **颜色不超过 5**，方块不超过 12。超过这个数，手机小屏读图成本会盖过思考乐趣（实验：7×7→9×9 只让 par 从 5.9→6.6，但读图明显变慢）。
3. **每 10 关必须换一次"问题类型"**：S1 问"怎么消"，S2 问"从哪绕"，S3 问"消不消"，S4 问"先消谁"，S5 问"能不能再省一步"。

## 8. 10 个代表关卡

> 每张卡片只写"这关为什么值得留在 50 关里"。完整解法见 `B_最小关卡验证.md` 与 `research/levels_md.md`。

### 8.1 第 6 关「双通道」（par 6 / 上限 10）

```
      1 2 3 4 5
  1   · A · ■ A
  2   · · · · ·
  3   B · B · C
  4   · C · · ·
  5   · · ■ · ·
```

**考点**：两条竖井各有一对，先送谁下去？`R1C2` 的 A 必须停到 `R3C2`，再横送到 `R3C5`——**第一次要求"横竖组合"的铺垫**。铺垫 3 步、中腹停靠 1 次、贪心失败。

### 8.2 第 9 关「十字墙」（par 7 / 上限 10）

```
      1 2 3 4 5
  1   C ■ B · ·
  2   A · A · ·
  3   D ■ · · ·
  4   B · · · C
  5   · · D · ·
```

**考点**：墙把直路切成两段，方块必须从缺口绕。**这是"边境高速路"第一次被真正打断**：想从左边到右边，必须经过第 3 列。

### 8.3 第 13 关「对角」（par 8 / 上限 11）

```
      1 2 3 4 5
  1   ■ · · · ·
  2   C D · · ·
  3   D C · · ·
  4   ■ · · · A
  5   · B · B A
```

**考点**：四个角各有一对，出口只有一个。8 步里有 4 步是铺垫，**是"纯安排"而非"纯消除"的一关**。首步有 8 种保持最优——多解，但每条解都要规划通道。

### 8.4 第 18 关「挤一挤」（par 9 / 上限 12）

```
      1 2 3 4 5
  1   · · B ■ A
  2   · C ■ ■ ·
  3   B E · A ·
  4   · · · C ·
  5   · D D E ·
```

**考点**：10 块、5 色、3 面墙。**能停的地方比想动的方块少**，玩家必须先"腾出一个车位"。中腹停靠 2 次，是 S2 的难度峰值。

### 8.5 第 22 关「只要红色」（par 5 / 上限 8）

```
      1 2 3 4 5
  1   · B A · C
  2   D · ■ A A
  3   C · · B ·
  4   · · ■ ■ D
  5   · · · · A
```

**考点**：目标切换的第一课。**别的颜色不是"要消的"，是"可以挪的墙"。** 玩家如果延续"清场"思维，会多花 2–3 步。

### 8.6 第 27 关「给红色让路」（par 5 / 上限 7）

```
      1 2 3 4 5
  1   C A · ■ ·
  2   · A · · ·
  3   A · ■ · D
  4   B B ■ D ·
  5   · · C A ·
```

**考点**：清色关里最纯的"挪 vs 消"。`R4C4` 的 D 向右挪一格，给红 A 让出竖井——**如果把 D 消掉，反而少了一块刹车**。这是微创新的教科书关卡。

### 8.7 第 34 关「五色交错」（par 10 / 上限 12）

```
      1 2 3 4 5
  1   A · D ■ B
  2   · ■ C · ·
  3   D · · · ·
  4   C · · E E
  5   · B A · ■
```

**考点**：五色同场，**每一对都可能是别人的路**。10 步、5 次消除、3 次中腹停靠，是 S4 的难度峰值。

### 8.8 第 38 关「红海」（par 7 / 上限 9）

```
      1 2 3 4 5
  1   A A A · C
  2   · B · · D
  3   A ■ · ■ A
  4   · · B · D
  5   · ■ · A C
```

**考点**：6 块红、3 对，**先让哪一对碰头，决定后面还有没有路**。分组选择第一次成为主问题。

### 8.9 第 44 关「红海之外」（par 7 / 上限 8）

```
      1 2 3 4 5
  1   · B C A ·
  2   A D ■ D ·
  3   C · A · ·
  4   · A · ■ B
  5   · · A A ■
```

**考点**：上限只比 par 多 1。**没有冗余步数**，任何一次"先消了再说"都会直接卡死。这是 S5 的门槛关。

### 8.10 第 50 关「最后一撞」（par 10 / 上限 11）

```
      1 2 3 4 5 6
  1   · · · E B ·
  2   ■ · · · · ■
  3   · · · · · C
  4   E D A · · E
  5   · · · C B E
  6   · D ■ A · ·
```

**考点**：12 块、5 色、6 次消除、上限 11。**"路"本身就是资源**：前 3 步都在拆远处的对，为的是给中间的 A 留出两条竖井。作为毕业关，它同时用到停靠、借位、让路、分组。

### 9.1 竖屏（主）

```
┌─────────────────────────────┐
│  ‹ 返回      第 3 关      ♪ │  ← 顶栏 56px
│                             │
│   目标  清空全场             │  ← 目标 chip
│   步数  3 / 6               │  ← 数字（上限到 12 时仍清楚）
│                             │
│  ┌───────────────────────┐  │
│  │                       │  │
│  │    ·  A  ·  ·  ·      │  │
│  │    ·  ·  ·  ■  ·      │  │
│  │    ·  ·  ·  A  ·      │  │  ← 棋盘：正方形，居中
│  │    ·  B  ·  B  ·      │  │     边长 = min(屏宽-32, 屏高*0.5)
│  │    ·  ·  ·  ·  ·      │  │
│  │                       │  │
│  └───────────────────────┘  │
│                             │
│   ┌───────┐  ┌───────┐      │
│   │ 撤销  │  │ 重开  │      │  ← 主操作区
│   └───────┘  └───────┘      │
│                             │
│        ( 提示 · 呼吸 )       │  ← 卡住 15s 或连续 3 步无消除后出现
└─────────────────────────────┘
```

- **步数用数字不用点阵**：`3 / 6` 在手机上更省空间；50 关阶段上限会到 12，点阵会过密。这是 11-07 按实机效果做的调整。
- **目标用 chip**：清场 = 一个空棋盘图标；清色 = 该颜色的方块图标 + "只清红色"。
- **规则第一次进入时用弹窗讲**：4 条短句 + "我明白了！"；关掉后记住，可随时点右上角 `?` 重看。底部规则条仍然常驻，用亮色 + 半透明底板，不再是一行灰字。
- **右上角常驻 `?` 与 🔊**：音量开关一键静音，状态持久化；不藏在二级菜单里。
- **撤销/重开常驻**，不做二级菜单。手指够得到（底部 1/5 区域）。
- **棋盘不滚动、不缩放**，整屏固定。

### 9.2 关键状态

| 状态 | 表现 |
|---|---|
| 空闲 | 棋盘呼吸光 0.5% 缩放，提示"可以拖" |
| 按住 | 方块放大 1.06，其余方块降饱和 20% |
| 拖拽中 | 方向箭头 + 落点虚影（半透明方块）+ 被撞目标描边（同色 = 金色，异色 = 灰色） |
| 动画中 | 输入锁定；撤销/重开仍可点（点击会立即结算当前动画） |
| 胜利 | 棋盘上方浮出星星（逐个弹出 120 ms）+ 步数结算 + "下一关" |
| 步数耗尽 | 半透明条 + [撤销一步] [重开]；不遮挡棋盘 |
| 阶段完成 | 10 关星星网格 + "继续" |

### 9.3 颜色与可读性

- 方块造型统一：圆角方块 + 左上柔光，**内部不放任何符号**。
  - 早期版本给每种颜色配了圆形/三角/星形，实机看起来像"按钮"或"方向指示"——尤其蓝色三角会被误读成"点了就往箭头方向走"。已全部移除。
- **颜色是唯一区分维度**：A 红、B 蓝、C 绿、D 琥珀、E 紫。前 10 关最多同时 3 色，之后最多 5 色。
- 对比度目标：方块与背景 ≥ 3:1；高光只做左上柔光，不做满屏白点，避免"高亮 = 可点"的误解。
- 后续若加色弱辅助，只用**边缘纹理**（圆点 / 斜纹）区分，不引入箭头等方向性符号。

## 10. H5 技术思路

### 10.1 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 渲染 | **Canvas 2D** | 50 个方块以内，2D 足够；DOM 做拖拽会有布局抖动 |
| 框架 | **无**（原生 ES Module） | 10 天预算，不引入构建链与依赖 |
| 输入 | **Pointer Events** | 一套代码覆盖触摸/鼠标/触控笔 |
| 音频 | **WebAudio 合成** | 零素材、零加载、可动态调音高 |
| 存档 | **localStorage** | 单机进度，无需后端 |
| 部署 | 静态文件（GitHub Pages / 任意 CDN） | 无服务端 |

### 10.2 文件结构

```
/
├─ index.html
├─ styles.css
├─ src/
│  ├─ main.js        // 启动、场景切换、主循环
│  ├─ game.js        // 规则内核（从 research/engine.mjs 移植）
│  ├─ render.js      // Canvas 绘制
│  ├─ input.js       // 拖拽状态机
│  ├─ anim.js        // 缓动与时间轴
│  ├─ audio.js       // 合成音效
│  ├─ save.js        // 进度读写
│  └─ levels.js      // 50 关数据（由 JSON 生成）
└─ tools/
   ├─ verify.mjs     // 关卡校验（复用 research/solver_fast.mjs）
   └─ gen.mjs        // 关卡生成 + 过滤
```

### 10.3 规则内核接口（与验证脚本一致）

```js
// 纯函数，无 DOM，可在 Node 里跑——这是"设计即代码"的关键
// 名称与 research/engine.mjs 对齐：genA / applyA / goalA
parse(rows) -> state
genMoves(state) -> Move[]          // research 里叫 genA；{r,c,d,res:'move'|'pop',tr,tc,br,bc}
apply(state, move) -> state        // research 里叫 applyA；不修改入参
isGoal(state, goal) -> boolean     // research 里叫 goalA（清色目标由 goal 参数决定）
```

> 游戏本体与校验脚本共用同一份规则实现，**避免"设计时能过、游戏里过不了"**。这是本项目最重要的工程决策。

### 10.4 关卡数据格式

```json
{
  "id": 3,
  "stage": 1,
  "name": "借它停车",
  "goal": "clear",
  "targetColor": null,
  "limit": 6,
  "par": 3,
  "teach": "有时候挡住去路的方块不是障碍，而是刹车——先别急着消掉它。",
  "rows": ["#######", "#.A...#", "#...#.#", "#...A.#", "#.B.B.#", "#.....#", "#######"],
  "sol": [
    { "r": 1, "c": 2, "d": "D", "res": "move" },
    { "r": 3, "c": 2, "d": "R", "res": "pop" },
    { "r": 4, "c": 2, "d": "R", "res": "pop" }
  ]
}
```

- `rows` 用字符画，方便人读、方便 diff。
- `sol` 只用于"提示"与自动化测试，不在正常游玩时暴露。
- `par` 由 `tools/verify.mjs` 写入，**不允许手填**。

### 10.5 拖拽状态机

```
idle
 └─ pointerdown(onBlock) → pressed (记录起点)
      ├─ move < 10px → 仍是 pressed
      ├─ move ≥ 10px → dragging (锁定主轴，显示箭头/虚影)
      │    └─ pointerup → commit(move) → animating → idle
      └─ pointerup < 10px → selected (仅高亮，不扣步；可选的无障碍"点选 + 点方向"模式，P3)
```

- **主轴锁定**：`|dx| > |dy| * 1.2` 判横向，避免斜拖抖动。
- **落点虚影**：松手前就显示 `apply(state, move)` 的结果格，**让玩家在犯错前看到结果**。
- **误触保护**：`pointercancel` / 移出棋盘 → 取消，不扣步。

### 10.6 动画与主循环

- `requestAnimationFrame` + 时间戳 delta，**不用 setInterval**。
- 动画是"状态机 + 时间轴"，不是 CSS transition（Canvas 没有）。
- 滑动：每格 55 ms，`easeOutQuad`，总时长 `min(260, cells*55)`。
- 消除：顿帧 40 ms（冻结 rAF 更新）→ 180 ms 缩放消失。
- **输入锁**：动画期间 `inputLocked = true`；动画结束前 1 帧解锁，保证手感连贯。

### 10.7 存档

```js
localStorage['zhuang.progress.v1'] = {
  unlocked: 12,              // 已解锁到第几关
  stars: { "1": 3, "2": 3 }, // 关卡 -> 星数
  settings: { sound: true }
}
```

- 每次通关写一次；写失败（隐私模式）静默降级，不阻断游戏。
- 提供"重置进度"（设置页，双击确认）。

### 10.8 性能与兼容

| 指标 | 目标 |
|---|---|
| 首屏可交互 | < 1.5 s（4G） |
| 包体 | < 200 KB（无图片、无音频文件） |
| 帧率 | 60 fps（中端安卓）；最低 30 fps |
| 兼容 | iOS Safari 15+ / Chrome 90+ / 微信内置浏览器 |
| 分辨率 | `devicePixelRatio` 缩放；棋盘尺寸取 `min(vw-32, vh*0.5)` |

### 10.9 明确不做

- 不做服务端、不做账号、不做云存档。
- 不做关卡编辑器 UI。
- 不做横屏专属布局（横屏时棋盘居中、上下留白即可）。

## 11. 开发与测试优先级

> 排序原则：**先证明"能玩"，再证明"好玩"，最后才好看。** 任何一步不达标，不进入下一步。

| 优先级 | 内容 | 完成标准 | 预算 |
|---:|---|---|---|
| **P0** | 规则内核 + 单关可玩 | 加载第 1 关，拖拽能滑、能消、能判胜；控制台无错 | 1 h |
| **P0** | 前 3 关 + 教学文案 + 步数/撤销/重开 | 3 关连续可玩；第 3 关不看提示也能过 | 1 h |
| **P1** | 关卡校验流水线 | `node tools/verify.mjs` 输出 `levels=50 failed=0`；par 自动写入 | 1 h |

## 12. 风险与对策

| 风险 | 触发信号 | 对策 |
|---|---|---|
| **边境高速路**（最优解退化为"滑到边上再配对"） | 某阶段连续 5 关的解法都是"先滑到边界" | 关卡入库硬性过滤：中腹停靠 < 1 的关卡不进 S2 之后 |
| **后期重复** | 玩家在第 30 关后跳过教学文案、重开率上升 | 每 10 关换问题类型（§7.3）；S3 引入清色 |
| **拖拽误触** | 试玩中 > 10% 的操作方向错误 | 方向虚影 + 主轴锁定 + 10 px 阈值；必要时放大格子 |
| **步数太紧变背答案** | 重开率 > 30% | 按阶段给 slack；重开率超标的关卡 +1 步 |
| **清色关目标歧义** | 玩家问"别的颜色要不要消" | 目标 chip 明确写"只清红色"；首次出现时用 1 行文案说明 |
| **手机性能** | 中端机掉到 30 fps 以下 | 粒子数上限 6；不用阴影模糊；离屏 canvas 缓存棋盘底图 |
