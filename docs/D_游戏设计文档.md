# D. 游戏设计文档（GDD）

**《撞个正着》**
一句话：**拖一个方块，它会一直滑到底；撞上同色方块，两块一起消失。**

| 项 | 内容 |
|---|---|
| 类型 | 2D 滑块解谜 / 休闲 |
| 平台 | 移动端 H5（竖屏优先），桌面浏览器可玩 |
| 单局时长 | 20–90 秒 |
| 关卡数 | 50（5 阶段：8 / 10 / 12 / 10 / 10，含 4 关教学；#4 起引入“只清目标色”） |
| 操作 | 单指拖拽（唯一操作） |
| 目标用户 | 等车、排队时想"动一下脑子"的轻度玩家 |
| 商业化 | 无。比赛作品，不做内购/广告 |
| 技术 | 原生 ES Module + Canvas 2D + WebAudio，无框架、无构建 |

> **证据说明**：本文件中所有 par、上限、方块数、贪心失败、乱滑通关率均来自 `research/` 的模拟器与求解器（可复跑）；所有"玩家会觉得 / 会记住 / 会想再来一关"都是**策划预测**，尚未经过真人试玩，需按 `docs/E` 的 11-14 试玩验证。

---

## 1. 设计目标与非目标

### 目标

1. **3 秒看懂，30 秒上手**：第 1 关不需要任何文字也能玩。
2. **每关只问一个问题**："这一对，现在消还是等会儿消？"
3. **失败不挫败**：没有时间压力，步数用完可以无限撤销。
4. **50 关不靠堆规模**：难度来自目标切换、几何、步数收紧，不来自"更大的盘 + 更多的块"。

### 非目标

- 不做剧情、角色、养成、联机、排行榜。
- 不做连锁、重力、道具、多指操作。
- 不追求美术精度：方块 + 圆角 + 颜色 + 一个符号，够了。
- 不做关卡编辑器（内部用 JSON + 脚本，不面向玩家）。

## 2. 核心规则（唯一权威版本）

### 2.1 棋盘

- 矩形网格，外圈是边界，内部可放**墙**（`#`）、**空位**（`.`）、**方块**（5 种颜色 A–E）。
- 每格至多一个方块。

### 2.2 一次操作

玩家按住一个方块，向上下左右任一方向拖动，松手后：

1. 方块沿该方向**逐格滑动**。
2. 下一格是**墙或边界** → 停在最后一个空格。
3. 下一格是**异色方块** → 停在它旁边，**不推动它**。
4. 下一格是**同色方块** → 移动块与目标块**同时消失**；移动块不占目标格。
5. 若移动 0 格且没有消除 → **无效操作，不扣步数**（松手回弹）。

### 2.3 目标与步数

- **清场关**：清空全部方块。
- **清色关**：只清除指定颜色；其他颜色可以留，也可以消（但消一对要花一步，还可能少一块可借的"刹车"）。
- 每关有步数上限。**用完且未达成目标 = 失败瞬间**（可撤销，见 §6）。
- 一次操作**最多消一对**。无连锁、无重力、无补位。

### 2.4 术语（内部统一叫法）

| 术语 | 含义 |
|---|---|
| **滑** | 移动但没消除 |
| **撞 / 消** | 与同色方块对撞并双双消失 |
| **停靠** | 方块停在非边界位置（通常是被墙或异色块挡住） |
| **中腹停靠** | 停在棋盘内部（非最外圈）——核心技巧的度量指标 |
| **借位** | 故意让某块停在某处，为下一步做铺垫 |
| **边境高速路** | 方块总能滑到边界、边界天然形成汇合线的结构性漏洞 |

## 3. 微创新：消除 = 拆墙

### 3.1 一句话

> 因为消除**只移除、不新增**，所以每消一对，等于**拆掉两堵墙**。核心抉择不是"消哪一对"，而是"**这一对现在消，还是留着当刹车**"。

### 3.2 为什么这条创新成立（不是包装）

| 证据 | 数据 |
|---|---|
| 最优解里"停在内部"的铺垫步普遍存在 | 13 个精选关卡中 **11 关**含至少 1 次铺垫步，其中 **10 关**含关键的中腹停靠 |
| 关键停靠步不可跳过 | 第 2 关禁掉 `R5C4↑` 后 par 从 3 → 4；7 个合法首步里只有 1 个保持 par。第 3 关同理：禁掉 `R1C2↓` 或先消 B，par 3 → 4 |
| "看到能消就消"不是正确策略 | 贪心策略在 **11/13 关**失败 |
| 乱走不能过关 | 第 6 关起，随机乱滑在 par 步内通关率 **0%** |

### 3.3 它改变了哪一种决策

| 普通消除游戏 | 《撞个正着》 |
|---|---|
| 消掉 = 得分 + 腾空间 | 消掉 = 得分，但**同时拆掉了两块可用的挡板** |
| 棋盘越空越好 | 棋盘**太空反而没地方停车** |
| 目标是"找能消的" | 目标是"**安排它们停在哪**" |

这就是全部创新。**不再加第二条。**

## 4. 反馈与奖励

### 4.1 一次操作的反馈时序（关键：让因果可见）

| 时间 | 表现 | 目的 |
|---:|---|---|
| 0 ms | 按住方块 → 放大 1.06、投影一层暗影 | 确认"抓住了" |
| 拖动 > 10 px | 判定主轴，出现**方向箭头** + **落点虚影** + 被撞目标描边 | 让玩家在松手前就知道结果 |
| 松手 | 输入锁定，开始滑动 | 防连点 |
| 每格 55 ms（总时长上限 260 ms） | 方块 easeOutQuad 滑行，带 0.9→1 的拖影 | 滑动有重量 |
| 撞墙/异色 | 停靠瞬间 60 ms 挤压（scaleX 1.12 / scaleY 0.9），回弹 | "刹住了"的手感 |
| 撞同色 | 40 ms 全屏顿帧 → 两块放大到 1.15 → 180 ms 缩到 0 + 6 个碎片粒子 | 消除的"砰" |
| 消除后 80 ms | 轻震 4 px / 手机 vibrate(15) | 触觉确认 |
| 结算前 200 ms | 剩余步数逐个跳动 | 给"省了几步"一个仪式 |

### 4.2 音效（WebAudio 合成，不加载素材）

| 事件 | 声音（首版实现） |
|---|---|
| 滑动 | 520 → 300 Hz 三角波，100 ms，低音量 |
| 撞墙 / 无效操作 | 170 → 110 Hz 方波，90 ms（"顶住了"） |
| 消除 | 620 Hz + 940 Hz 双音，130 ms（上行"叮"） |
| 通关 | C5-E5-G5-C6 琶音，每音 200 ms |
| 界面（关闭玩法卡 / 音效开关） | 740 Hz 正弦，50 ms |

> 静音开关常驻右上角（🔊/🔇），状态写入 localStorage；默认开声音。浏览器要求先有一次交互，第一次 pointerdown 时解锁 AudioContext。
> 首版不做"抓起"音：高频短音在连续拖动时容易变成噪音。

### 4.3 奖励结构

| 层级 | 奖励 | 规则 |
|---|---|---|
| 单关 | **1–3 星** | 3 星 = 步数 ≤ par；2 星 = 步数 ≤ par + 2；1 星 = 在步数上限内通关 |
| 单关 | "一次过"徽章 | 全程未使用撤销且 ≤ par + 1 |
| 阶段 | 阶段完成页 | 展示本阶段 10 关的星星总数 |
| 全局 | 50 关全三星 | 标题页显示"全清"标记（不做排行榜） |

**没有金币、没有体力、没有抽奖。** 奖励只做两件事：告诉玩家"你走得比最少步多几步"，以及"你可以再优化"。

### 4.4 失败反馈（不惩罚）

- 步数归零且未达成目标 → 棋盘上方浮出半透明条：**"步数用完了 · 差一点"**
- 两个按钮：**[撤销一步]**（退还 1 步）、**[重开]**
- 不做"失败音效"、不做红色闪烁、不扣星星（本来就没拿到）。
- 目标色没清完但还能动 → **不提前判负**，让玩家自己发现"已经没救了"。

## 5. 失败 / 重试 / 撤销

| 机制 | 规则 | 理由 |
|---|---|---|
| **撤销** | 无限次；回到上一步的棋盘 + 退还 1 步；反向动画 120 ms | 休闲玩家不该因为一次手滑重开 |
| **重开** | 任意时刻可用；无确认弹窗；重置步数与棋盘 | 确认框比误触更烦 |
| **失败** | 只有"步数耗尽"一种；无时间限制、无生命值 | 失败必须可归因于"我想错了"，不是"我手慢" |
| **提示** | 空闲 45 秒或连续 2 次重开后，提示按钮开始呼吸；点击高亮最优解的下一步（数据来自关卡 `sol`），**使用后本关最高 2 星** | 防卡死，同时保留三星的含金量 |
| **无效操作** | 0 位移且无消除 → 回弹，不扣步、不进撤销栈 | 避免"点一下也扣步"的隐形惩罚 |

**关于"撤销退还步数"的说明**：这看起来让步数上限失效，但实际不会——撤销只能退回**已经走过的**局面，玩家仍然必须自己想出正确顺序。步数上限约束的是"这一遍尝试的长度"，撤销约束的是"不许无限试错而不付时间成本"。对休闲玩家，时间成本已经足够。

## 6. 前 8 关完整设计

> 八关的目标不是"好玩"，是**在 8 分钟内把"拖—撞—挡—停—借—换目标—配对—绕墙—中腹停靠—借块停车"这条规则链走一遍**。11-07 按试玩反馈重排：原第 1、2 关合并（两关的通关思路相同），原第 3 关前移为第 2 关，新第 3 关把"借它停车"这个核心抉择摆到玩家面前。11-08 按试玩反馈新增第 4 关「只要红色」：第 2、3 关都属于"同一种问题（怎么停、怎么消）"，所以第一次真正换问题类型要更早——第 4 关直接把"目标"换掉。第 5 关再把**目标色从一对加到两对**：谁跟谁配成一对，第一次由玩家自己决定。第 6 关第一次让**墙把棋盘切开**：三对颜色分居左右两条竖井，每一对都必须自己选一条通道绕过去。第 7 关把停车点从中腹的墙里"造"出来：两格墙横在棋盘中间，三对串成 B→A→C 一条链，消掉一对才给下一对让路。第 8 关做 S1 收尾：两格墙改成对角，第三对第一次**借别的方块停车**，而借来的刹车本身也是之后要被消掉的一块。

### 6.1 第 1 关「碰一下」（原第 1、2 关合并）

```
      1 2 3 4 5
  1   A · B · A
  2   · · · · ·
  3   · · · · ·
  4   · · · · ·
  5   · · B · ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 6（par 2） |
| 方块 | 4（A×2，B×2） |
| 教学文案 | "拖动方块，它会滑到撞上东西为止。撞同色一起消失；异色会挡路，但它也有一对。" |
| 二次提示 | "先消掉中间挡路的 B：把它往下拖，A 的路就通了。要是 B 已经消了，直接让两个 A 对撞。" |

**通关步骤**

1. `R1C3` 的 B 向下 → 撞 `R5C3` 的 B → 双消
2. `R1C1` 的 A 向右 → 撞 `R1C5` 的 A → 双消

**设计意图**：把原第 1 关的"同色对撞"和原第 2 关的"异色挡路"压进同一关。玩家第一反应多半是拖 A；A 只滑到 `R1C2` 就被 B 挡住——这一下同时教了"滑到底"和"异色不会让路"。再把 B 消掉，A 的路就通了。少一关，但两个规则都在，而且第一次"被挡住"不扣命、不失败。

**失败点**：先拖 A 会被挡住，多花 1 步（3 步通关，2 星）；上限 6，不会失败。A 被挡住后也可以拖走再重试。

**验收标准**：不看文案的玩家能在 30 秒内通关；第一下拖 A 被挡住后，能在 1 次尝试内改拖 B；能说出"B 挡着，所以先消 B"。

### 6.2 第 2 关「停在墙边」（原第 3 关前移）

```
      1 2 3 4 5
  1   · · · · ·
  2   · · · · ·
  3   · · B ■ ·
  4   · · A · ·
  5   · · B A ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 5（par 3） |
| 方块 | 4（A×2，B×2） |
| 教学文案 | "墙也是刹车：方块会停在墙边，而「停下的位置」往往正是另一块需要的位置。" |
| 二次提示 | "别只想着滑到底：往上拖 A，墙会把它停在另一块 A 旁边。" |

**通关步骤**

1. `R5C4` 的 A 向上 → 被 `R3C4` 的墙挡住，停在 `R4C4`
2. `R4C3` 的 A 向右 → 撞 `R4C4` 的 A → 双消
3. `R3C3` 的 B 向下 → 撞 `R5C3` 的 B → 双消

**设计意图**：玩家直觉是"往上拖会滑到顶"，但墙让它停在 `R4C4`——正好贴在另一块 A 旁边。**"墙替你踩了刹车"** 这个结果完全符合规则，却是第一次遇到。

**数据支撑**：7 个合法首步里**只有 1 个**保持 par；禁掉它，par 从 3 → 4（仍在上限 5 内，不会卡死，但拿不到三星）。

**失败点**：先把 `R3C3` 的 B 往上挪开（`R3C3` 向上）会多花 1 步：A 仍能靠墙停车，但 B 要再滑一次才能消，4 步通关拿 2 星。**这是"可接受的失败"：不卡死，但玩家能感到"我好像绕远了"。**

**验收标准**：玩家在 30 秒内主动把 A 往上拖（而不是先动 B）；通关后能复述"墙把它挡住了，正好停在另一块旁边"。

### 6.3 第 3 关「借它停车」（11-08 重做：par 3 → 4）

```
      1 2 3 4 5
  1   · · · · ·
  2   · · · A B
  3   · · · · ·
  4   · A · B ·
  5   · · · · ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 6（par 4） |
| 方块 | 4（A×2，B×2），无内墙 |
| 教学文案 | "挡住去路的方块不只是障碍：把它推开，它就成了你下一次停车的刹车。" |
| 二次提示 | "首步别急着消对：把右下角的 B 往右推到墙边，它就能把另一块 A 停在你需要的位置。" |

**通关步骤**

1. `R4C4` 的 B 向右 → 贴墙停在 `R4C5`
2. `R4C2` 的 A 向右 → 被 `R4C5` 的 B 挡住，停在 `R4C4`
3. `R2C4` 的 A 向下 → 撞 `R4C4` 的 A → 双消
4. `R2C5` 的 B 向下 → 撞 `R4C5` 的 B → 双消

**设计意图**：这是全篇第一次"刹车位置要自己造"。前两关的刹车（墙、在场的异色块）都是给定的，看到了就能用；这一关的蓝块一开始并不在需要的位置上——必须先把 `R4C4` 的 B 推到墙边，它才成为 `R4C2` 那个 A 的停车位。**"推它 / 消它"取代了"借它 / 消它"，是核心抉择的第一次升级。**

**数据支撑**：13 个合法首步，只有 1 个保持 par（`R4C4` 向右）；其余 11 个首步都是 5 步、1 个是 6 步；禁掉关键步后 par 从 4 → 5。所有可达局面 **deadEnds = 0**。

**失败点**：不先推 B 就直接消对，A 会一路滑到边线，之后还要多花一步把两块 A 调回同一行，变成 5 步 2 星；不卡死，只是少一颗星。

**验收标准**：玩家在 40 秒内尝试"先动 B 而不是先消对"；通关后能说出"B 被我推过去，正好给 A 当了刹车"。

- 失败只在"步数用尽且未清空"时触发；弹窗提供「撤销一步」（退还 1 步）与「重开本关」，不会出现只能看广告/退出重来的死路。

| 方块 | 4（A×2 目标色，B×2） |
| 教学文案 | "目标变了：不用清空，只要红色全部消失。"（只讲目标，不解释蓝块） |
| 二次提示 | "左上角的红块一步也动不了：把旁边那块蓝推到最右边，红块才有路——而且正好停在它旁边。" |

**通关步骤**

1. `R1C2` 的 B 向右 → 一路滑到墙边 `R1C5`
2. `R1C1` 的 A 向右 → 被 B 挡住，停在 `R1C4`
3. `R1C4` 的 A 向下 → 被 `R4C4` 的 B 挡住，停在 `R3C4`
4. `R3C4` 的 A 向右 → 撞 `R3C5` 的 A → 双消，红色清空即通关

**设计意图**：前三关都是"把棋盘清空"，问题是同一类：怎么停、怎么消。第 4 关把**目标本身**换掉，这是 50 关里第一次真正的"问题类型"变化。同时它解决了上一版的一个毛病：蓝块只是摆设。现在**蓝块就是解法本身**——第一块既是"开关"（不把它推开，左上角的红被墙和蓝夹死，一步也动不了），又是"刹车"（推开之后，红正好停在它前面）；第二块再把红停到第三行。两块蓝各管一段，没有一块是多余的。

**为什么是 2 块蓝而不是 3 块**：par 4 = 3 步非消除 + 1 次双消。非消除步最多碰 3 块蓝，而第一块还要"先被推走、再当刹车"占掉 2 步——留给第三块蓝的位置根本不存在。上一版给 3 块、par 3（只有 2 步非消除），第三块在数学上注定是装饰，这正是"看着冗余"的根因。**块数要跟解法步数对齐，而不是越多越像难关。**

**为什么"清空"走不通**：2 块蓝正好成对，清空全场是**做得到**的——但要 6 步，上限只有 5 步。也就是说"清空"不是被规则禁止，而是被步数预算挡住。这比"给奇数块蓝、物理上不可能"更好：玩家感受到的是"我自己选择不做"，而不是"系统不让我做"。

**数据支撑**：8 个合法首步，只有 1 个保持 par（`R1C2` 向右）；把蓝块往下推（同样是"推开它"，但位置不对）是 5 步；**禁掉所有"推蓝块 / 借蓝块停车"的走法后直接无解**；清场 par = 6 > 上限 5。所有可达局面 **deadEnds = 0**。

**为什么不是"更难的同类关"**：第 3 关的难点是"先推块再借停"，和"怎么消 A"仍是同一个问题；把参数调紧只会变成"同题多算一步"。换目标才能让玩家换一种思考方式。这也是第 7 节难度杠杆的第一条。

```
  2   A · · · ·

  4   · A · · ·
  5   · · · A ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | **只清红色** / 6（par 4） |
| 方块 | 6（A×4 = 两对，B×1，C×1），1 面内墙 |
| 教学文案 | "红块这次有 4 块——两对。谁跟谁配成一对，由你来定；蓝块和绿块各能当一次刹车。" |
| 二次提示 | "先凑竖着的一对：第三行那块红往左滑，绿块会把它停在上面那块红的正上方。" |

**通关步骤**

1. `R3C3` 的 A 向左 → 被 `R3C1` 的绿块挡住，停在 `R3C2`（正好压在 `R4C2` 的红块头上）
2. `R3C2` 的 A 向下 → 撞 `R4C2` 的 A → 双消（竖着的一对）
3. `R5C4` 的 A 向上 → 被 `R1C4` 的蓝块挡住，停在 `R2C4`（正好和 `R2C1` 的红块同排）
4. `R2C1` 的 A 向右 → 撞 `R2C4` 的 A → 双消（横着的一对）

**设计意图**：第 4 关只换目标，红块仍只有一对，玩家的动作还是"把两块凑到一起"。第 5 关把目标色加到 4 块——**谁跟谁配，第一次变成玩家要自己决定的事**。四块红没有一块是现成能消的（18 个首步里 0 个消除），玩家必须先回答"我打算怎么分这两对"，再去找每对的停靠点。两块非目标色各管一件事：绿块挡住竖着那一对的滑行线，蓝块挡住横着那一对。

> **一处设计订正**：50 关表里这一关原本写作"先消哪一对，另一对就少一块刹车"。复核规则后发现这句在现行规则下**不成立**——同色一旦在同一直线上就必然双消，红块永远不可能给红块当刹车（`moveFrom` 里 `v === col` 直接返回 `pop`）。所以第 5 关的真实机制改成"配对由玩家决定 + 蓝绿各当一次刹车"，表格与文案同步改正。

**为什么"清空"这关连试都试不了**：蓝、绿各只有一块，永远凑不成对，所以清空全场**物理上不可能**（测试里断言 `solve({goal:'clear'}) === Infinity`）。这和上一版第 4 关的写法不同，但在这里是合理的：目标色第一次有两对，玩家本来就要把注意力放在"红和红怎么配"上。

**数据支撑**：18 个合法首步，0 个是消除，只有 2 个保持 par（`R3C3` 向左、`R5C4` 向上，对应两对的先后顺序可换）；其余 16 个首步全部 ≥5 步。**只禁掉"碰蓝块"或只禁掉"碰绿块"，par 都会退化为 5**——两块非目标色各值一步，都不能省。6 步内可达 90386 个局面，**死局 0**。

### 6.7 第 6 关「双通道」（11-08 新增）

```
      1 2 3 4 5
  1   A C · · B
  2   · · ■ · ·
  3   B · ■ A ·
  4   · · ■ · ·
  5   · · · · C
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 10（par 6） |
| 方块 | 6（A×2、B×2、C×2），3 格内墙（第 3 列第 2–4 行） |
| 教学文案 | "中间的墙把棋盘分成左右两条竖井，只有最上面一行和最下面一行能过去。两块同色要碰面，先想好走哪条通道。" |
| 二次提示 | "先从上面走：把左上角的 C 往下放，它会在最下面一行等着和另一块 C 会合。" |

**通关步骤**

1. `R1C2` 的 C 向下 → 顺着左井落到底，停在 `R5C2`
2. `R1C1` 的 A 向右 → 穿过第一行的上通道，被 `R1C5` 的 B 停在 `R1C4`
3. `R1C4` 的 A 向下 → 撞 `R3C4` 的 A → 双消
4. `R1C5` 的 B 向左 → A 让开之后，B 才能一路滑到 `R1C1`
5. `R1C1` 的 B 向下 → 撞 `R3C1` 的 B → 双消
6. `R5C2` 的 C 向右 → 穿过第五行的下通道，撞 `R5C5` 的 C → 双消

**设计意图**：第 5 关的问题是"谁跟谁配"，第 6 关的问题变成"配好了之后，怎么让它们见面"。三对颜色各有**一块在左井、一块在右井**，中间一列墙只在第一行和第五行留出口——于是每一对都必须自己选一条通道绕过去。更关键的是第 2–4 步的顺序耦合：A 必须先被 B 停在 `R1C4` 才能消掉；A 消掉之后，B 才滑得到 `R1C1` 去和下面那块 B 会合。**同一个 B，既是 A 的刹车，又是自己下一对的主角**——它先当障碍、再当解法，一步都不能提前。

**为什么不是"更难的配对关"**：第 5 关的两对互不依赖，先竖后横都一样；第 6 关的三对共享两条通道，先动哪一块会直接改变后面能不能停到正确的位置。这是从"配对"到"调度"的第一次升级，也是 S2「学会绕」的入口。

**墙数说明（对 GDD 原表的一处订正）**：50 关表原本把这一关记为 2 格墙。实际要把 5×5 内场切成左右两条竖井，第 3 列至少要在第 2–4 行连断 3 格（第 1、5 行各留一个出口）才成立，所以是 **3 格墙**。它不是"多摆几块墙加难"，而是把棋盘切成两条通道的结构件——难度来自"三对都必须跨井 + 先动 B 会丢停车位"，不是墙的数量。S1 的墙数区间相应从 0–2 放宽到 0–3。

**数据支撑**：13 个合法首步，只有 2 个保持 par（先 `R1C2` 下，或先 `R3C4` 上——先做 C 那对或先做 A 那对都行）；其余 11 个是 7–8 步（2 星）。**13 个首步全部仍能在 10 步上限内通关**，走错只掉星、不会一步走进死路。看起来最该先动的右上 B，一动就把 A 的停车位弄丢，退化为 8 步。10 步内可达 **1,510,377** 个局面，**死局 0**。

### 6.8 第 7 关「借墙停车」（11-08 新增）

```
      1 2 3 4 5
  1   · B · A C
  2   · · · B ·
  3   · ■ ■ · A
  4   · · · · ·
  5   · · · · C
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 8（par 5） |
| 方块 | 6（A×2、B×2、C×2），2 格内墙（第 3 行第 2–3 列） |
| 教学文案 | "两格墙横在棋盘中间：把方块推向墙，它会停在半路——停下的位置，正好能接住另一块。" |
| 二次提示 | "先让左上角的 B 往下滑，墙会把它停在第二行；再往右，它就能撞上另一块 B。" |

**通关步骤**

1. `R1C2` 的 B 向下 → 被 `R3C2` 的墙停在 `R2C2`
2. `R2C2` 的 B 向右 → 撞 `R2C4` 的 B → 双消（第 4 列就此打开）
3. `R3C5` 的 A 向左 → 被 `R3C3` 的墙停在 `R3C4`
4. `R1C4` 的 A 向下 → 撞 `R3C4` 的 A → 双消（第 5 列就此打开）
5. `R1C5` 的 C 向下 → 落到底，撞 `R5C5` 的 C → 双消

**设计意图**：第 2 关的墙就在方块旁边，"滑过去自然停"；第 7 关的墙横在中腹，**停车位置要自己造**：B 先借上面那格墙停在 `R2C2`，A 再借下面那格墙停在 `R3C4`。更重要的是顺序——B 不消掉，`R2C4` 的 B 会顶住第 4 列，A 下不去；A 不消掉，`R3C5` 的 A 会挡住第 5 列，C 落不到底。三对刚好串成 **B→A→C 一条链**，每一对都是下一对的"开门人"。

**为什么不是重复第 2 关**：第 2 关是 4 块 / 1 格墙 / 单次停靠的"认识墙"；第 7 关是 6 块 / 3 色 / 两格墙 / 两次中腹停靠 + 三对顺序耦合。难度不是墙变多，而是**停车点和顺序都得算**。两格墙也都是承重的：拿掉任意一格，方块停不到正确位置，par 从 5 退化为 6。

**数据支撑**：13 个合法首步，0 个开局可消，恰好 2 个保持 par（先 `R1C2` 下，或先 `R3C5` 左——先做 B 那对或先做 A 那对都行）；其余 11 个是 6–7 步（2 星），**13 个首步全部仍能在 8 步上限内通关**。8 步内可达 **263,616** 个局面，**死局 0**。

### 6.9 第 8 关「小结·三对」（11-08 新增）

```
      1 2 3 4 5
  1   · · B C ·
  2   · ■ C · ·
  3   · · · A ·
  4   · B · ■ ·
  5   · A · · ·
```

| 项 | 值 |
|---|---|
| 目标 / 步数 | 清场 / 9（par 6） |
| 方块 | 6（A×2、B×2、C×2），2 格内墙（`R2C2`、`R4C4` 对角） |
| 教学文案 | "S1 最后一关：把 6 块全部清空。墙、边框、别的方块都能让方块停下——这一关三对都得借一次刹车。" |
| 二次提示 | "顶上的 C 先往下滑：它会被 A 停在第二行，正好和另一块 C 凑成一对。" |

**通关步骤**

1. `R1C4` 的 C 向下 → 被 `R3C4` 的 A 停在 `R2C4`（**借块停车**）
2. `R2C3` 的 C 向右 → 撞 `R2C4` 的 C → 双消
3. `R4C2` 的 B 向右 → 被 `R4C4` 的墙停在 `R4C3`（**内墙停靠**）
4. `R1C3` 的 B 向下 → 撞 `R4C3` 的 B → 双消（C 已让开第 3 列）
5. `R5C2` 的 A 向上 → 被 `R2C2` 的墙停在 `R3C2`（**内墙停靠**）
6. `R3C2` 的 A 向右 → 撞 `R3C4` 的 A → 双消，清场

**设计意图**：S1 收尾不是"再加一种墙"，而是把前三课合起来考——第 2、7 关的**墙当刹车**（两格对角墙各用一次）、第 3 关的**借别的方块停车**（第三对 C 借 A），以及第 6 关的**顺序耦合**（C 借的 A 必须活到最后；B 挡住 A 的启动路线；C 又挡住 B 的下落路线，三对串成 C→B→A）。

**为什么第三对不是"贴边停车"**：`R1C4` 的 C 只有两个方向——向右到边框，或向下。向右之后，`R2C3` 的 C 没有任何一步能直接撞到它；向下则会被 `R3C4` 的 A 停在 `R2C4`，下一步正好和 `R2C3` 的 C 双消。也就是说，**任何 6 步解都必须走这次借块停车**，它不是可选的花活。借来的 A 之后还要作为 A 那对的消除目标；先消 A 会拆掉 C 的停车位，代价是 8 步。

**为什么是 par 6 而不是 par 5**：6 块必须 3 次消除，par 6 = 3 次消除 + 3 次铺垫。三对正好各用一次铺垫：C 借块停车、B 借墙停车、A 借墙停车。par 5 只允许 2 次铺垫，必有一对"白送"，剩下那格墙就只能靠"封死更短路线"承重——玩家很难在盘面上感知到它。11-08 的搜索也证实了这个结构矛盾，所以第 8 关定为 par 6 / 上限 9。

**为什么是对角两格墙**：两格墙的布局枚举过 12 种。横排、竖排的 par4 双墙停骨架里，没有"拿掉任一格墙骨架就变慢"的样本；对角布局的 1,196 个骨架里有 316 个满足。对角让两格墙分别从两个方向提供"墙前一格"的停车位，B 和 A 各用一格，互相替代不了。

**数据支撑**：13 个合法首步，0 个开局可消，恰好 2 个保持 par（`R1C4` 下 / `R4C2` 右）；其余 7–8 步（2 星），13 个首步全部仍能在 9 步上限内通关。先动 `R3C4` 的 A 会拆掉 C 的停车位，退化为 8 步。拿掉 `(2,2)` 或 `(4,4)` 任意一格墙，par 都从 6 退化为 7。9 步内可达 **1,002,116** 个局面，**死局 0**。

**与第 7 关的区别**：第 7 关两格墙同向、C 是"消完就收尾"的尾巴，顺序是 B→A→C；第 8 关两格墙对角、第三对的铺垫是借块停车，借来的 A 还要在最后被消掉，顺序是 C→B→A。同样是"墙当刹车"，第 7 关考两次停靠，第 8 关考三种刹车（墙、墙、块）和它们之间的先后。

## 7. 50 关难度曲线

### 7.0 难度杠杆：先加决策，再加布景

> 这一节回答一个具体问题：**后面加难，是不是主要靠加颜色、加墙、扩大棋盘？** 不是。三者的性价比依次递减，而且加错了会让游戏"看起来更难，实际只是更难读图"。

**难度 ≈ 需要做的决策数 × 诱惑强度 × 走错的代价。** 真正的主杠杆只有四个，按优先级：

| 优先级 | 杠杆 | 具体做法 | 玩家感受 |
|---:|---|---|---|
| 1 | **目标切换** | 清场 → 只清目标色 → 只清某一对 / 某个区域 | "我原来一直在解错题" |
| 2 | **顺序耦合** | 先消 A 会让 B 失去刹车；先消 B 会让 A 没有落点 | "每一步都在给后面挖坑或铺路" |
| 3 | **停靠精度** | 必须停在某一格，且只被墙 / 异色块 / 边界三者之一接住 | "方向对了，但停错了" |
| 4 | **容错收紧** | 上限从 par+3 收到 par+1，诱惑步从"少一星"变成"直接失败" | "不敢乱试了" |

**三个布景杠杆**（重要，但不能当主菜）：

| 布景 | 真实作用 | 什么时候用 | 过度使用的代价 |
|---|---|---|---|
| 颜色数量 | 增加"哪些块算障碍"的读图成本 | S2 之后每 5 关 +1 色，最多 5 色 | >4 色时玩家主要在看颜色，不在算路径 |
| 墙体数量 | 制造停靠点、切断直路 | 每关 0–4 面，且每面墙都要有明确用途 | 墙多了会变成迷宫，"停在哪"变成"猜哪条能走" |
| 棋盘尺寸 | 拉长滑行距离、放下更多走廊 | S4 之后 7×7 → 9×9 | 研究实测：7×7 → 9×9 只让平均 par 从 5.9 → 6.6，但读图明显变慢 |

**结论**：颜色、墙、尺寸是**空间复杂度**，负责"棋盘看起来更复杂"；真正让玩家停下来的，是**目标、顺序、精度、容错**这四件事。所以第 4 关没有加任何颜色和尺寸，只是把"清空"换成"只清红色"，难度感就换了一档。

### 7.3 曲线的四条硬约束

1. **par 涨幅逐段收窄**：S1 2→6，S2 5→9，S3 3→7（目标变了，par 回落是故意的），S4 7→10，S5 7→10。**不允许单调上升**——S3 开头的"回落"是给玩家一次"我很行"的呼吸。
2. **颜色不超过 5**，方块不超过 12。超过这个数，手机小屏读图成本会盖过思考乐趣（实验：7×7→9×9 只让 par 从 5.9→6.6，但读图明显变慢）。
3. **每 10 关必须换一次"问题类型"**：S1 问"怎么消"（#4 先问"清什么"），S2 问"从哪绕"，S3 问"消不消"，S4 问"先消谁"，S5 问"能不能再省一步"。
4. **一次只换一个问题**：新关只允许比上一关多一个"没见过的判断"，其余变量复用。加颜色/加墙/加尺寸不算新问题，只是同一问题的布景；真正的加难按 7.0 的杠杆顺序来。

## 8. 12 个代表关卡

> 每张卡片只写"这关为什么值得留在 50 关里"。完整解法见 `B_最小关卡验证.md` 与 `research/levels_md.md`。

### 8.1 第 6 关「双通道」（par 6 / 上限 10）

```
      1 2 3 4 5
  1   A C · · B
  2   · · ■ · ·
  3   B · ■ A ·
  4   · · ■ · ·
  5   · · · · C
```

**考点**：三对颜色各有一块在左井、一块在右井，中间一列墙只在第 1、5 行留出口——**每一对都必须自己选一条通道**。`R1C2` 的 C 先落到 `R5C2` 预埋；`R1C1` 的 A 穿上门通道被 `R1C5` 的 B 停在 `R1C4` 消掉；**A 让开之后 B 才滑得到 `R1C1`**，再与 `R3C1` 的 B 双消；最后 C 从下通道收尾。同一个 B 先当 A 的刹车、再当自己那对的主角，提前动它就是 8 步。

### 8.2 第 7 关「借墙停车」（par 5 / 上限 8）

```
      1 2 3 4 5
  1   · B · A C
  2   · · · B ·
  3   · ■ ■ · A
  4   · · · · ·
  5   · · · · C
```

**考点**：两格墙横在中腹，**停车位置要自己造**。B 借上面那格墙停到 `R2C2`，消掉 `R2C4` 的 B，第 4 列才通；A 借下面那格墙停到 `R3C4`，消掉后第 5 列才通；C 最后落到底。三对串成 B→A→C 一条链，两格墙拿掉任意一格 par 都退化为 6。

### 8.3 第 8 关「小结·三对」（par 6 / 上限 9）

```
      1 2 3 4 5
  1   · · B C ·
  2   · ■ C · ·
  3   · · · A ·
  4   · B · ■ ·
  5   · A · · ·
```

**考点**：S1 的收尾。两格对角墙各当一次刹车，第三对 C 第一次**借 A 停车**；借来的 A 还要在最后被消掉。C 挡住 B 的下落路线，B 挡住 A 的启动路线，三对串成 **C→B→A**。拿掉任意一格墙 par 都从 6 退化为 7，先消 A 会拆掉 C 的停车位、退化为 8。

### 8.4 第 9 关「十字墙」（par 7 / 上限 10）

```
      1 2 3 4 5
  1   C ■ B · ·
  2   A · A · ·
  3   D ■ · · ·
  4   B · · · C
  5   · · D · ·
```

**考点**：墙把直路切成两段，方块必须从缺口绕。**这是"边境高速路"第一次被真正打断**：想从左边到右边，必须经过第 3 列。

### 8.5 第 13 关「对角」（par 8 / 上限 11）

```
      1 2 3 4 5
  1   ■ · · · ·
  2   C D · · ·
  3   D C · · ·
  4   ■ · · · A
  5   · B · B A
```

**考点**：四个角各有一对，出口只有一个。8 步里有 4 步是铺垫，**是"纯安排"而非"纯消除"的一关**。首步有 8 种保持最优——多解，但每条解都要规划通道。

### 8.6 第 18 关「挤一挤」（par 9 / 上限 12）

```
      1 2 3 4 5
  1   · · B ■ A
  2   · C ■ ■ ·
  3   B E · A ·
  4   · · · C ·
  5   · D D E ·
```

**考点**：10 块、5 色、3 面墙。**能停的地方比想动的方块少**，玩家必须先"腾出一个车位"。中腹停靠 2 次，是 S2 的难度峰值。

### 8.7 第 22 关「只要红色」（par 5 / 上限 8）

```
      1 2 3 4 5
  1   · B A · C
  2   D · ■ A A
  3   C · · B ·
  4   · · ■ ■ D
  5   · · · · A
```

**考点**：目标切换的第一课。**别的颜色不是"要消的"，是"可以挪的墙"。** 玩家如果延续"清场"思维，会多花 2–3 步。

### 8.8 第 27 关「给红色让路」（par 5 / 上限 7）

```
      1 2 3 4 5
  1   C A · ■ ·
  2   · A · · ·
  3   A · ■ · D
  4   B B ■ D ·
  5   · · C A ·
```

**考点**：清色关里最纯的"挪 vs 消"。`R4C4` 的 D 向右挪一格，给红 A 让出竖井——**如果把 D 消掉，反而少了一块刹车**。这是微创新的教科书关卡。

### 8.9 第 34 关「五色交错」（par 10 / 上限 12）

```
      1 2 3 4 5
  1   A · D ■ B
  2   · ■ C · ·
  3   D · · · ·
  4   C · · E E
  5   · B A · ■
```

**考点**：五色同场，**每一对都可能是别人的路**。10 步、5 次消除、3 次中腹停靠，是 S4 的难度峰值。

### 8.10 第 38 关「红海」（par 7 / 上限 9）

```
      1 2 3 4 5
  1   A A A · C
  2   · B · · D
  3   A ■ · ■ A
  4   · · B · D
  5   · ■ · A C
```

**考点**：6 块红、3 对，**先让哪一对碰头，决定后面还有没有路**。分组选择第一次成为主问题。

### 8.11 第 44 关「红海之外」（par 7 / 上限 8）

```
      1 2 3 4 5
  1   · B C A ·
  2   A D ■ D ·
  3   C · A · ·
  4   · A · ■ B
  5   · · A A ■
```

**考点**：上限只比 par 多 1。**没有冗余步数**，任何一次"先消了再说"都会直接卡死。这是 S5 的门槛关。

### 8.12 第 50 关「最后一撞」（par 10 / 上限 11）

```
      1 2 3 4 5 6
  1   · · · E B ·
  2   ■ · · · · ■
  3   · · · · · C
  4   E D A · · E
  5   · · · C B E
  6   · D ■ A · ·
```

**考点**：12 块、5 色、6 次消除、上限 11。**"路"本身就是资源**：前 3 步都在拆远处的对，为的是给中间的 A 留出两条竖井。作为毕业关，它同时用到停靠、借位、让路、分组。

```
┌─────────────────────────────┐
│ 第 4 关            4 / 5 ▦ ? 🔊 │  ← 顶栏：左=关号+关名，右=步数+选关+帮助+静音

│  ┌───────────────────────┐  │
│  │                       │  │
│  │  A  B  ·  ·  ·        │  │
│  │  ■  ·  ·  ·  ■        │  │
│  │  ·  ·  ·  ·  A        │  │  ← 棋盘：正方形，居中
│  │  ·  ·  ·  B  ·        │  │     边长 = min(屏宽-32, 屏高*0.5)
│  │  ·  ·  ·  ·  ·        │  │
│  └───────────────────────┘  │
│                             │
│   ┌───────┐  ┌───────┐      │
```

- **步数用数字不用点阵**：`3 / 6` 在手机上更省空间；50 关阶段上限会到 12，点阵会过密。这是 11-07 按实机效果做的调整。
- **目标写进关卡名，不单独做 chip**：清场关叫「碰一下 / 停在墙边 / 借它停车」，清色关直接叫「只要红色」；常驻规则条第一句再说一遍目标。11-08 评估后认为单独的目标 chip 会挤占顶栏，且手机上"名字"比"图标"更快读懂。
- **规则第一次进入时用弹窗讲**：4 条短句 + "我明白了！"；关掉后记住，可随时点右上角 `?` 重看。底部规则条仍然常驻，用亮色 + 半透明底板，不再是一行灰字。
- **右上角常驻 `▦` / `?` / 🔊**：`▦` 打开选关页（见 9.4），音量开关一键静音且状态持久化，都不藏在二级菜单里。
- **撤销/重开常驻**，不做二级菜单。手指够得到（底部 1/5 区域）。
- **棋盘不滚动、不缩放**，整屏固定。

### 9.2 关键状态

| 状态 | 表现 |
|---|---|
| 空闲 | 棋盘呼吸光 0.5% 缩放，提示"可以拖" |
| 按住 | 方块放大 1.06，其余方块降饱和 20% |
| 拖拽中 | 方向箭头 + 落点虚影（半透明方块）+ 被撞目标描边（同色 = 金色，异色 = 灰色） |
| 动画中 | 输入锁定；撤销/重开仍可点（点击会立即结算当前动画） |
| 胜利 | 棋盘上方浮出星星（逐个弹出 120 ms）+ 步数结算 + "下一关" |
| 步数耗尽 | 半透明条 + [撤销一步] [重开]；不遮挡棋盘 |
| 阶段完成 | 10 关星星网格 + "继续" |

### 9.3 颜色与可读性

- 方块造型统一：圆角方块 + 左上柔光，**内部不放任何符号**。
  - 早期版本给每种颜色配了圆形/三角/星形，实机看起来像"按钮"或"方向指示"——尤其蓝色三角会被误读成"点了就往箭头方向走"。已全部移除。
- **颜色是唯一区分维度**：A 红、B 蓝、C 绿、D 琥珀、E 紫。前 10 关最多同时 3 色，之后最多 5 色。
- 对比度目标：方块与背景 ≥ 3:1；高光只做左上柔光，不做满屏白点，避免"高亮 = 可点"的误解。
- 后续若加色弱辅助，只用**边缘纹理**（圆点 / 斜纹）区分，不引入箭头等方向性符号。

### 9.4 选关页（11-08 新增）

- HUD 常驻 `▦`，点开全屏覆盖层：5 列 × 10 行共 50 格，可滚动。
- 每格显示：关卡数字；已解锁则显示 3 颗小星（按该关最好成绩换算）；未解锁显示 🔒 且不可点击。
- 当前关高亮描边；汇总行显示 `已获得 N 颗星 · 已开放 4 / 50 关`。
- 解锁规则：第 1 关永远开放；已通关、当前关、或前一关已通关 → 开放；其余锁定。
- 关闭方式：`Esc` / 点背景 / 「继续当前关」；通关最后一关后，「下一关」按钮变成「选关」。
- 卡片最大高度 `100dvh - 48px`，只让网格滚动，关闭按钮永远留在卡片内（480 / 568 高度实测通过）。

### 9.5 墙体可读性（11-08 重做）

- 外圈不再逐格画 24 个暗淡小方块，而是**一整块深色石框**：外沿高光 + 内沿阴影，像有厚度的边框。
- 内墙改成**亮一档的石块 + 斜向石纹 + 亮描边**，不再是几乎和背景同色的灰块。
- 三层亮度实测（画布中心采样）：方块 114–131 > 内墙 99 > 外框 51–81 > 空地 15（空地 alpha 15/255）。
- 目的：一眼分清"墙 / 能走的空地 / 方块"。此前的反馈是"墙有点暗淡"，本质是墙和阴影撞色。

## 10. H5 技术思路

### 10.1 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 渲染 | **Canvas 2D** | 50 个方块以内，2D 足够；DOM 做拖拽会有布局抖动 |
| 框架 | **无**（原生 ES Module） | 10 天预算，不引入构建链与依赖 |
| 输入 | **Pointer Events** | 一套代码覆盖触摸/鼠标/触控笔 |
| 音频 | **WebAudio 合成** | 零素材、零加载、可动态调音高 |
| 存档 | **localStorage** | 单机进度，无需后端 |
| 部署 | 静态文件（GitHub Pages / 任意 CDN） | 无服务端 |

### 10.2 文件结构

```
/
├─ index.html
├─ styles.css
├─ src/
│  ├─ main.js        // 启动、场景切换、主循环
│  ├─ game.js        // 规则内核（从 research/engine.mjs 移植）

   ├─ verify.mjs     // 关卡校验（复用 research/solver_fast.mjs）

```

### 10.3 规则内核接口（与验证脚本一致）

```js
// 纯函数，无 DOM，可在 Node 里跑——这是"设计即代码"的关键
// 名称与 research/engine.mjs 对齐：genA / applyA / goalA
parse(rows) -> state
genMoves(state) -> Move[]          // research 里叫 genA；{r,c,d,res:'move'|'pop',tr,tc,br,bc}
apply(state, move) -> state        // research 里叫 applyA；不修改入参
isGoal(state, goal) -> boolean     // research 里叫 goalA（清色目标由 goal 参数决定）
```

> 游戏本体与校验脚本共用同一份规则实现，**避免"设计时能过、游戏里过不了"**。这是本项目最重要的工程决策。

### 10.4 关卡数据格式

```json
{
  "id": 3,
  "stage": 1,
  "name": "借它停车",
  "goal": "clear",
  "targetColor": null,
  "limit": 6,
  "par": 3,

  "rows": ["#######", "#.A...#", "#...#.#", "#...A.#", "#.B.B.#", "#.....#", "#######"],
  "sol": [
    { "r": 1, "c": 2, "d": "D", "res": "move" },

    { "r": 4, "c": 2, "d": "R", "res": "pop" }

```

- `rows` 用字符画，方便人读、方便 diff。
- `sol` 只用于"提示"与自动化测试，不在正常游玩时暴露。
- `par` 由 `tools/verify.mjs` 写入，**不允许手填**。

### 10.5 拖拽状态机

```
idle
 └─ pointerdown(onBlock) → pressed (记录起点)
      ├─ move < 10px → 仍是 pressed
      ├─ move ≥ 10px → dragging (锁定主轴，显示箭头/虚影)
      │    └─ pointerup → commit(move) → animating → idle
      └─ pointerup < 10px → selected (仅高亮，不扣步；可选的无障碍"点选 + 点方向"模式，P3)
```

- **主轴锁定**：`|dx| > |dy| * 1.2` 判横向，避免斜拖抖动。
- **落点虚影**：松手前就显示 `apply(state, move)` 的结果格，**让玩家在犯错前看到结果**。
- **误触保护**：`pointercancel` / 移出棋盘 → 取消，不扣步。

### 10.6 动画与主循环

- `requestAnimationFrame` + 时间戳 delta，**不用 setInterval**。
- 动画是"状态机 + 时间轴"，不是 CSS transition（Canvas 没有）。
- 滑动：每格 55 ms，`easeOutQuad`，总时长 `min(260, cells*55)`。
- 消除：顿帧 40 ms（冻结 rAF 更新）→ 180 ms 缩放消失。
- **输入锁**：动画期间 `inputLocked = true`；动画结束前 1 帧解锁，保证手感连贯。

### 10.7 存档

- 每次通关写一次；写失败（隐私模式）静默降级，不阻断游戏。
- 提供"重置进度"（设置页，双击确认）。

## 11. 开发与测试优先级

> 排序原则：**先证明"能玩"，再证明"好玩"，最后才好看。** 任何一步不达标，不进入下一步。

| 优先级 | 内容 | 完成标准 | 预算 |
|---:|---|---|---|
| **P0** | 规则内核 + 单关可玩 | 加载第 1 关，拖拽能滑、能消、能判胜；控制台无错 | 1 h |
| **P0** | 前 8 关 + 教学文案 + 步数/撤销/重开 | 8 关连续可玩；第 3–8 关不看提示也能过 | 1 h |
| **P1** | 关卡校验流水线 | `node tools/verify.mjs` 输出 `levels=50 failed=0`；par 自动写入 | 1 h |
| **P1** | 50 关数据 | 五阶段各 10 关，逐关有 par / 上限 / 可解性 | 3 h |
| **P2** | 反馈层 | 滑动、停靠、消除、震屏、音效、星级结算 | 1 h |
| **P2** | 界面与适配 | 顶栏/目标/步数/按钮；iPhone SE 到 iPad 不溢出 | 1 h |
| **P3** | 提示、存档、阶段页 | 卡住 45 s 出提示；刷新后进度不丢 | 1 h |

**砍功能顺序**（如果时间不够）：提示 → 阶段完成页 → 音效 → 粒子 → 存档。**永远不砍**：规则内核、前 8 关、50 关可解性校验、撤销。

## 12. 风险与对策

| 风险 | 触发信号 | 对策 |
|---|---|---|
| **边境高速路**（最优解退化为"滑到边上再配对"） | 某阶段连续 5 关的解法都是"先滑到边界" | 关卡入库硬性过滤：中腹停靠 < 1 的关卡不进 S2 之后 |
| **后期重复** | 玩家在第 30 关后跳过教学文案、重开率上升 | 每 10 关换问题类型（§7.3）；S3 引入清色 |
| **拖拽误触** | 试玩中 > 10% 的操作方向错误 | 方向虚影 + 主轴锁定 + 10 px 阈值；必要时放大格子 |
| **步数太紧变背答案** | 重开率 > 30% | 按阶段给 slack；重开率超标的关卡 +1 步 |
| **清色关目标歧义** | 玩家问"别的颜色要不要消" | 目标 chip 明确写"只清红色"；首次出现时用 1 行文案说明 |
| **手机性能** | 中端机掉到 30 fps 以下 | 粒子数上限 6；不用阴影模糊；离屏 canvas 缓存棋盘底图 |
