# 《撞个正着》迭代优化过程文档

> H5 滑动解谜 · 固定 50 关 · v1.0
> 文档日期：2026-11-12

## 1. 迭代概览

| 阶段 | 时间 | 主要产出 | 关键问题 |
| --- | --- | --- | --- |
| 玩法验证 | 11-05 | 三套候选玩法、模拟器与求解器、选型结论 | 哪个机制能撑住 50 关且可验证 |
| 原型与首批关卡 | 11-06 – 11-08 | 第 1–18 关、选关页、墙体重绘 | 前 3 关教学是否成立、关卡是否重复 |

整个迭代围绕三条主线：

1. **玩法先被验证，再被包装。** 先用求解器证明“这个机制有真选择”，再投入 UI 和美术。
2. **每章只换一个问题。** 不靠加颜色、加墙、扩棋盘制造难度，而是换目标、换停法、换顺序。
3. **每个反馈都要落到可复测的改动。** 评审里说“手感差”，就拆成拖拽阈值、落点预览、停靠挤压、消除顿帧等具体项；说“320px 被裁”，就用 `scrollWidth / clientWidth` 实测。

## 2. 玩法验证期：先证明再开工

### 2.1 三个候选

| 方案 | 核心操作 | 结论 |
| --- | --- | --- |
| A 碰碰消 | 拖一个方块滑到底，撞同色一起消失 | 采用，86 分 |
| B 同色齐动 | 选颜色和方向，该色所有方块一起滑 | 保留为备选，62 分 |
| C 重力轮盘 | 消一对相邻同色，重力转 90° | 放弃，50 分 |

关键不是“谁更原创”，而是“一次操作能否同时产生我想要的结果和合理的意外”。A 的消除只移除不新增，因此每消一对等于拆掉两块刹车——这个副作用让“什么时候消”成为真决策。

### 2.2 先定验收指标

在写第一行游戏代码前，先定下可复算的指标：

- **par**：求解器算出的最少步数。
- **贪心失败**：看到能消就消，能否在 par+1 步内通关。
- **乱滑 @ par**：随机乱走，在 par 步内通关的概率。
- **中腹停靠**：最优解里“停在棋盘内部”的铺垫步数量。
- **不可解状态数**：走错后还有没有救。

这些指标后来贯穿了 50 关的生产：贪心能过的关卡淘汰，随机能过的关卡淘汰，墙和颜色必须“承重”。

## 3. 原型期：前三关和第一次重排

### 3.1 第一版：规则能跑，但教学不顺

第 1 关先做了最小闭环：拖方块、滑到底、同色相撞消失。第 2、3 关分别加入“墙边停”和“借块停车”。

试玩后发现的第一个问题不是难度，而是**前两关在教同一件事**：都在问“怎么停”，只是盘面不同。玩家没有获得新的问题类型。

### 3.2 第一次重排：合并、前移、造一个新第 3 关

改动：

- 原第 1、2 关合并为新的第 1 关，先让玩家完整经历一次“滑动—停住—同色消”。
- 原第 3 关前移为第 2 关，用墙边停车建立“停靠点”概念。
- 新第 3 关「借它停车」把核心抉择提前：停车位置不再给定，要先把蓝块推到墙边，它才成为停车位。par 从 3 调到 4，13 个首步里只有 1 个保持 par。

结果：前三关从“同一问题的三个变体”变成“滑动 → 停墙 → 借块造停车位”的连续教学。

### 3.3 第二次重排：第 4 关提前换目标

继续试玩后发现，直到很后面才出现“目标不是清空”的关卡。玩家会误以为游戏只有一种赢法。

于是把第 4 关改成「只要红色」：红 4 块、蓝 1 块、绿 1 块；蓝绿永远消不掉，但必须分别被推开、当刹车。清场需要 6 步，而上限只有 5 步——“清空”这条路在物理上走不通，玩家必须接受“只清红”。

这是第一次用**目标切换**而不是**增加障碍**制造新问题。第 5 关再把目标色从一对加到两对，让“谁跟谁配成一对”第一次由玩家决定。

## 4. 内容扩张期：把 50 关做成一条产线

### 4.1 每关都走同一条流程

1. 生成候选盘面（颜色、墙位、目标、上限）。
2. A\* 求 par，记录首步数量、最差首步、死局数量。
3. 淘汰贪心或随机乱滑能过的“假关卡”。
4. 做承重检查：
   - 拆掉整组墙后 par 必须下降；
   - 有非目标色的关卡，拿掉该整色后 par 必须变化。
5. 人工挑选解法形态不同、读图干净的盘面。
6. 写入游戏，用内核回放最优解，跑全量测试。

### 4.2 章节推进

| 章节 | 迭代重点 | 典型改动 |
| --- | --- | --- |
| S1 #1–#8 | 建立“停车”与“拆刹车” | #8 首次加入锚块：拖不动、只能同色撞 |
| S2 #9–#18 | 墙从刹车变成路障 | 缺口、回廊、窄门、假出口；#18 双锚块 |
| S3 #19–#30 | 换目标，让非目标色必须有用 | 只清红、目标色四块、目标色本身被钉住 |
| S4 #31–#40 | 多对颜色串成耦合链 | 一处停车影响下一处；#40 最后一对 |
| S5 #41–#50 | 收窄容错，做毕业考 | 上限压到 par+1 / par+2；#50 三合一 |

### 4.3 两个被数据否掉的直觉

- **“块越多越像难关”是错的。** 第 4 关曾经放 3 块蓝，但 par 4 只允许 3 次非消除，第三块蓝没有任何承重用途。删到 2 块后，关卡反而更纯。
- **“拆墙一定变简单”也是错的。** #15 拆掉某格墙后 par 反而变慢，因为那格墙是解法里的刹车。承重检查因此从“墙越多越难”改成“墙必须被用上”。

### 4.4 中期问题：难度曲线出现平台

到 S4 时，关卡数量够了，但试玩反馈开始出现“中段像在重复做同一道题”。处理方式不是加新颜色，而是：

- 把“目标切换”从 S3 提前到第 4 关；
- 在 S4 把“一对的结果成为另一对的刹车”做成硬约束；
- 在 S5 把上限压到 par+1 / par+2，让“顺序错一步”真的会失败；
- 每关只保留一个核心新问题，避免同一关同时教两件事。

## 5. 体验评审：从“能玩”到“愿意玩”

11-10 做了一轮外部玩家 / 评委视角评审。评审给出的综合分是 **6.0 / 10**：核心创意 8.5、关卡严谨度 8.0，但操作手感 4.5、信息架构 5.0、可访问性 3.0。结论很直接：“像一份优秀的关卡设计稿 + 一个能跑的原型，还不是一款打磨完成的休闲游戏。”

这轮评审之后，按 P0 / P1 / P2 分批修，规则、par、上限一个都没动。

### 5.1 P0：先修“看起来能点但没反应”

| 问题 | 改动 | 验证 |
| --- | --- | --- |
| 动画期间点撤销被静默吞掉 | 撤销改为排队，动画结束优先执行 | `moves 1 → 点撤销 → 动画结束 moves 0` |
| 320–360px HUD 被裁 | 目标前缀在窄屏隐藏，目标允许换行，右侧按钮不压缩 | 320px 无横向溢出，7 字关名不裁切 |
| 选关页不定位、开放数写死 | 汇总改用真实解锁数；打开时把当前关滚到可视区；加阶段标题与迷你三星 | 第 50 关打开后当前格完整可见 |
| 生产包暴露 `window.__zgz` | 只在 localhost / 127.0.0.1 / `[::1]` / file 下挂调试钩子 | GitHub Pages 上完全不存在 |
| 31/50 关拿不到 1★ | 不动上限，只改星级换算：3★=par，2★=par+max(1, round((limit−par)/2))，其余 1★ | `limit=par+2` 的关卡终于有 1★ |

### 5.2 手感：把“拖一下”拆成可测的反馈

- 拖拽阈值从 10px 提到 20px，并支持“拖回起点 12px 内松手 = 取消”，减少误触。
- 拖拽预览重做：半透明落点虚影 + 同色虚线路径 + 按方块颜色着色的方向箭头；撞异色描边、撞墙画厚边、同色相撞画环。
- 停靠反馈：150ms 挤压回弹 + 一圈弱冲击环 + 撞墙 / 撞异色的不同音高。
- 消除反馈：60ms 顿帧 + 冲刺 + 放大消失 + 8 颗程序化碎片 + 冲击环。
- **去掉振动**：第一版屏幕轻震被反馈“看着屏幕在晃”，先减弱到原来的 1/5.5，仍然被指出观感不好，最终整段删除，连 `navigator.vibrate` 一起移除。

### 5.3 提示与失败：让提示是“救急”，不是“跳过”

第一版提示会永久扣星，玩家刷星无望；点击提示还会直接打开完整解法。

逐步改成：

- **三层提示**：第 1 层只讲方向，免费；第 2 层指出下一步，扣 1★；第 3 层打开完整解法，再扣 1★。
- **扣星只在本次尝试内有效**：重开、再玩一次、从选关页重进都会恢复 3★ 机会；历史最高星仍保留。
- **看解法二次确认**：第一次点变成“确认看解法”，6 秒不点自动回退。
- **死局弱提示**：后台 Worker 只在“按剩余步数确实赢不了”时提示，不提前剧透；超预算时当作“不知道”，不乱报。
- **撤销倒放**：撤销会把滑行和消除反向播放，让玩家看清刚才发生了什么。

### 5.4 可访问性与布局

- 五种颜色各加一种边缘线型：红实线、蓝虚线、绿点线、黄点划线、紫双环；色弱玩家不靠颜色也能区分。
- 支持键盘：方向键选块、空格拿起、方向键滑动、Esc 放下；画布有完整 `aria-label`，关键操作通过 `role="status"` 播报。
- 支持日间 / 夜间主题、80%–200% 缩放、320px 窄屏、横屏“请竖屏游玩”提示。
- 结算页加入最优解回放；挑战关（#42 / #47 / #48 / #50）在选关页与 HUD 加 ⚑ 标识，进关先播一句预期提示。

### 5.5 评审里没有做完的部分

评审提到“中段新鲜感”“手感上限”“颜色对比”等问题，有些只做到了可接受，而不是完美：

- 手感仍以清晰为主，没有做更夸张的震屏和粒子；
- 没有做真人长周期试玩，难度曲线仍以求解器 + 短时试玩为准；
- 中段（S3–S4）的题型仍有相似感，靠目标切换和耦合链缓解，而不是彻底重构。

这些限制在 v1.0 里保留，作为后续版本的方向。

## 6. 特殊机制迭代：把“停”拆成三种

### 6.1 锚块（#8 → #18 → #30）

| 关卡 | 改动 | 结果 |
| --- | --- | --- |
| #8 钉子户 | 单颗红锚块，拖不动、挡路、只能同色撞 | par 6 / 上限 9；8 个首步只有 1 个保持 par；锚块必须最后一步被撞掉 |
| #18 挤一挤 | 两颗锚块：绿钉先拆、黄钉留最后 | par 8 / 上限 11；11 个首步只有 1 个保持 par |
| #30 小结·钉红 | 目标色自己被钉住，两颗红钉拖不动 | 只清红；par 7 / 上限 9；红钉第 5 / 7 步被拆 |

每一步都做了同一组回归：锚块拖不动、异色被挡、同色撞掉、可动化后 par 不变（证明压力来自顺序而不是省步）。

### 6.2 最后一对（#40 → #49）

不再问“停在哪”，而是问“什么时候允许消”。黄色一对可以当刹车挪动，但只剩两块时必须是整盘最后一撞。

- #40：par 9 / 上限 11，旧最优解第 6 步消黄直接非法；
- #40：新最优解把消黄挪到第 9 步；
- #40：把规则关掉后 par 仍是 9，说明难度来自“留到最后”，不是加步数；
- #49：紫色改为最后一对，par 仍为 10 / 上限 12；原最优解最后一步本来就是消紫，因此路线不用改，只是把“巧合”变成明确规则。

### 6.3 泊位与三合一（#45 → #50）

泊位把“停”变成必须命中的位置：彩色虚线格，对应颜色停进去一次即永久打勾，通关要求所有泊位都停过。

#45 先单独教泊位：

- 盘面中间一格标成紫色泊位，紫块停进去一次即打勾；
- 原最优解第 3 步本来就把紫块停在这里，因此 par 保持 9 / 上限 11；
- 紫色整色拿掉后泊位永远停不满，确认无解；
- 拆掉整组内墙后 par 不再下降（9 → 9），说明路线已经被泊位锁住，而不是靠墙撑难度。

#50 再把锚块、泊位、最后一对叠在一起：

- 12 块、5 色、4 墙，par 10 / 上限 12；
- 16 个首步里 4 个保持 par，最差 12；
- 红块第 2 步进红泊位，第 3 步才够得到红锚块；
- 蓝块第 6 / 7 步借黄块、再进蓝泊位；
- 紫块第 10 步最后一撞；
- 拆掉整组内墙 par 仍是 10；拿掉红或蓝整色直接无解（泊位永远停不满）。

从 #45 的单独教学，到 #49 的顺序强化，再到 #50 的三合一，三种“刹车”第一次在同一盘面上互相牵制：先停哪个、再拆哪个、哪个留到最后，成为毕业考的唯一问题。

## 7. 盘面符号：让标记自己说话（11-11）

三种机制的图示原本只在文档里用文字解释。新玩家看到钉帽、虚线格、方格旗时，仍要猜“这代表什么”。

这一轮做了三件事：

- 标题页规则下方加三枚紧凑图例：图标 + 名称 + 一句话（钉子 / 拖不动，泊位 / 停同色，最后一对 / 最后才消）。
- 玩法卡加入“后期关卡的盘面标记”三行完整说明。
- 小图标与 Canvas 里的钉帽、虚线停车格、方格旗一一对应，深浅主题共用。

验证：360×800、320×640、390×844 三档标题页无横向溢出；320px 下三列图例各自放得下；玩法卡按既有 `max-height` 滚动；截图像素比对确认三种图标真实渲染。

## 8. 评委视角最后一轮（11-12）：按官方答疑逐条对照

### 8.1 依据：官方答疑给出的评审约束

官方答疑文档明确了评分三维度（玩法设计 50%、关卡体验 30%、迭代打磨 20%），以及几条直接影响呈现的约束：评委时间有限，可能不会逐关打通 50 关，建议提供关卡选择入口；评审在浏览器里用鼠标打开链接直接试玩；美术精致不加分，视觉的作用是让机制被看懂；失败之后，玩家要能说出自己为什么失败；较难关在连续失败时要给玩家新信息。

### 8.2 第一批改动：把“作品已经有、评委看不见”的部分补出来

逐条对照这些约束自查，发现五个差距：

| 官方依据 | 差距 | 改动 |
| --- | --- | --- |
| 评委时间有限，建议提供关卡选择入口 | 默认逐关解锁，第 50 关的巧思要打通 49 关才能看见 | 默认 50 关全关可选（`?locked=1` 恢复逐关解锁），选关页标注“推荐从第 1 关开始” |
| 失败要能说出原因 | 失败页只说“差一点”，既不说差什么也不给回头路 | 失败诊断：列出还差几对 / 几个泊位；Worker 从历史快照找“最后还能赢的一步”，提供「回到第 N 步（还有救）」一键回退 |
| 新机制先学后组合 | 钉子 / 泊位 / 最后一对 / 目标切换第一次出现时没有单独说明，帮助页一屏铺开 | 机制首见弹规则卡，只讲该机制；同一关有多条未讲规则时合并成一张「一次讲清」；帮助页后期规则收进折叠 |
| 信息要清楚 | 目标进度只在部分时刻出现 | HUD 常驻「还差 N 对」「泊位 x/y」；剩 1–2 步时优先提示步数 |
| 交互为鼠标优化 | 鼠标悬停无任何提示，评委先要“试”哪些块能拖 | 可拖方块悬停显示 `grab` 与描边，钉子显示 `not-allowed` |

另有两处小修：目标色关卡消掉非目标色时，明确提示「不算目标」（避免把“消了一对”误记成“推进了目标”）；#40 / #45 首次引入「最后一对」/「泊位」各放宽 1 步上限，par 与预置解法不变。

### 8.3 第二批改动：复核发现的两处口径不一致

第一批落地后，模拟评委路径逐项复核（跳关 → 规则卡 → 三层提示 → 失败回退 → 解法面板 → 鼠标悬停），又发现两处信息矛盾，继续修：

| 问题 | 判断依据 | 改动 | 验证 |
| --- | --- | --- | --- |

## 10. 复盘

### 做对了什么

- **先写求解器，再写关卡。** 50 关的 par、上限、死局、承重都有数据，不靠“感觉差不多”。
- **每章换问题，不换皮。** 从“怎么停”到“从哪绕”到“哪些该留”到“什么时候消”，每一章都在改决策。
- **反馈能落地。** 外部评审的“手感差”“HUD 被裁”“提示太强”都被拆成具体改动并复测。
- **机制叠在主线里。** 锚块、泊位、最后一对没有另开模式，而是长在 #8 / #18 / #30 / #40 / #45 / #49 / #50 这些主线关卡里；其中 #45 / #49 是提交前的试点，用来把机制教学前移。
- **把官方答疑当评审清单用。** 评委的时间约束、鼠标操作、失败原因可说，逐条对照自查；11-12 的两批改动全部来自这份对照，其中第二批（HUD / 解法面板口径统一）正是“自己模拟评委玩一遍”才暴露出来的。

### 还能更好

- 中段题型的相似感仍在，后续可以增加更多“目标 + 障碍”的组合，而不是继续加关卡数。
- 手感受时间限制，仍以清晰、克制为主；如果继续做，可以补更完整的撞击反馈与音效层次。
- 还没有长周期真人试玩数据，难度曲线目前以求解器和短时试玩为准。

### 这一版的目标

把一句话规则讲清楚，把 50 关做扎实，让玩家在某一刻意识到：

> 原来这块一直用来刹车的方块，现在必须被消掉。

如果这个瞬间成立，这一版就成立。
